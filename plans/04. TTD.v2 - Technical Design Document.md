# 1. Introduction

## 1.1 Purpose

This document defines exactly how the platform is built under SAD v2.0: **vertical slices only**, one application, one database schema with foreign keys, same-transaction side effects. It is self-contained: it restates everything a developer needs, including the parts that did not change from v1.

Chain of documents: SRD (what) → SAD v2 (structure) → USAC (stories) → **TDD v2 (how, per slice)**.

## 1.2 What Changed From TDD v1.0

| Topic | TDD v1.0 | TDD v2.0 |
| --- | --- | --- |
| Projects | Module projects, `.Contracts` projects, BuildingBlocks, hosts | One `Todo.Server` project, two test projects |
| Database | Schema per module, no cross-schema foreign keys | One schema, **foreign keys everywhere they apply** |
| Cross-feature access | `IWorkspaceAccess`, `ITodoAccess`, `IAssignmentQuery`, `ITodoTagQuery`, `ICategoryAccess`, … | Shared services (Section 4) that query `AppDbContext` directly; tag, category and assignee filters are plain joins |

| Reporting | `todo_facts` projection | Direct SQL on operational tables |
| Background work | Outbox dispatchers per module, consumers | Five small background slices |
| Architecture tests | Assembly rules (ARCH-01..11) | Namespace rules (AT-01..09) |
| API contract | Section 7 and 8 of v1 | **Unchanged**: same routes, status codes, error codes and resource shapes (restated in Sections 7 and 8) |
| Role matrix, state machines, field limits, security defaults | as v1 | **Unchanged** (restated) |

# 2. Technical Conventions

## 2.1 Identifiers, Time, Enumerations

| Topic | Convention |
| --- | --- |
| Primary keys | `uuid`, generated in code with `Guid.CreateVersion7()`. Never by the client |
| Timestamps | `timestamptz`, UTC only, `DateTimeOffset` with zero offset, property names end in `At` |
| Time source | Inject `TimeProvider`. `DateTime.UtcNow` is forbidden (AT-05) |
| Local date/time | Only for recurrence: `timestamp without time zone` plus IANA `time_zone_id` |
| Time zones | IANA ids validated with NodaTime TZDB. Default `UTC` |
| Enumerations | Stored as `text` with `CHECK`. JSON uses PascalCase strings. Never integers |
| Soft delete | Nullable `deleted_at` with a global EF query filter. `IgnoreQueryFilters()` only in allow-listed slices (AT-07) |
| Naming | EF Core snake\_case convention; one schema `app` |

## 2.2 Field Limits (proposed)

| Field | Limit | Field | Limit |
| --- | --- | --- | --- |
| Todo title | 1–200 | Comment body | 1–5,000 |
| Todo description | 0–10,000 | Workspace name | 1–100 |
| Subtask title | 1–200 | Workspace description | 0–1,000 |

## 2.3 Pagination

`GET /api/v1/todos?page=1&pageSize=25&sort=dueAt&direction=asc`. `page` ≥ 1; `pageSize` default 25, max 100 (above 100 is a 400, not clamped); `sort` must be in the slice's allow-list (400 `invalid_sort_field`); every sort ends with `id` as tiebreaker. Response: `{ items, page, pageSize, totalCount, totalPages }`.

## 2.4 Error Contract (US-PLAT-003)

RFC 9457 Problem Details, `application/problem+json`:

```json
{ "type": "validation-error", "title": "Validation failed", "status": 400, "code": "validation_failed",
  "detail": "The request contains invalid fields.", "correlationId": "0HN7F2K3",
  "errors": { "title": ["Title is required."] } }
```

`code` is the stable machine-readable value the frontend switches on. `detail` is safe for display and never contains stack traces, SQL or internal ids. `correlationId` equals the trace id and the `X-Correlation-Id` header.

| ErrorKind | HTTP | Typical codes |
| --- | --- | --- |
| Validation | 400 | `validation_failed`, `invalid_sort_field`, `if_match_required` |
| Unauthenticated | 401 | `unauthenticated`, `invalid_credentials`, `session_revoked` |
| Forbidden | 403 | `permission_denied`, `account_locked`, `email_not_confirmed` |
| NotFound | 404 | `not_found` |
| Conflict | 409 | `concurrency_conflict`, `invalid_state_transition`, `duplicate_membership`, `email_already_registered` |
| Gone | 410 | `invitation_expired`, `token_expired`, `retention_expired` |
| PayloadTooLarge | 413 | `export_too_large` |
| RateLimited | 429 | `rate_limited` (with `Retry-After`) |
| Unexpected | 500 | `internal_error` |

**Disclosure rule:** if the caller may not know a resource exists (another user's personal todo, a workspace they are not in), return **404**. If they can see it but may not perform the operation, return **403**. `AccessDecision` (Allowed, Hidden, Denied) makes this consistent.

## 2.5 Concurrency and Idempotency

- `Version` is mapped to `xmin` and returned as `ETag: W/"<xmin>"`. `PATCH` and `PUT` updates require `If-Match` (missing → 400 `if_match_required`; stale → 409 `concurrency_conflict`).
- State transitions (`complete`, `reopen`, `archive`, `cancel`, `revoke`) are idempotent: repeating the call on a target already in the final state returns 200 or 204 without a second side effect. Entity methods return `true` when state changed and `false` when nothing changed; the slice writes side effects only on `true`.
- Worker slices are idempotent through unique constraints and guarded `UPDATE ... WHERE status = ...` statements (Section 10).
- Optional `Idempotency-Key` header on `POST /todos` and `POST /workspaces`, stored 24 h in `idempotency_keys` (SHOULD in R1).

## 2.6 Security Defaults (proposed)

| Setting | Value |
| --- | --- |
| Password | min length 12, no composition rules, common-password blocklist |
| Lockout | 5 failures, 15 minutes |
| Auth cookie | `__Host-todo.auth`, HttpOnly, Secure, SameSite=Lax. Persistent 14 days sliding; non-persistent session cookie, 12 h absolute |
| Token lifetimes | email confirmation 24 h, password reset 1 h, email change 1 h, invitation 7 days |
| CSRF | `X-XSRF-TOKEN` header on every `POST`, `PUT`, `PATCH`, `DELETE` |
| Rate limits | auth endpoints 5/min per IP+email; general API 300/min per user |
| Headers | HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` on invitation and reset pages |

## 3.2 Program.cs and Run Roles

```csharp
var builder = WebApplication.CreateBuilder(args);
var role = builder.Configuration["Hosting:Role"] ?? "all";          // api, worker or all

builder.Services
    .AddCommon(builder.Configuration)            // TimeProvider, ICurrentUser, ProblemDetails, rate limiting, OpenAPI
    .AddPersistence(builder.Configuration)       // AppDbContext (UseSnakeCaseNamingConvention, one schema)
    .AddIdentityAndSecurity(builder.Configuration)
    .AddSharedServices()                         // everything in Services/
    .AddSlices();                                // scans Features/**: nested Handler classes, validators, IEndpoint

if (role is "worker" or "all") builder.Services.AddBackgroundSlices();   // hosted services in Features/**

var app = builder.Build();
if (role is "api" or "all") { app.UseCommonPipeline(); app.MapSliceEndpoints(); }
app.MapHealthChecks("/health/live"); app.MapHealthChecks("/health/ready");
app.Run();
```

Migrations are applied by a separate command (`dotnet Todo.Server.dll --migrate`), never during normal startup.

## 3.3 Slice Conventions

- File `Features/<Area>/<SliceName>/<SliceName>.cs` (or `Features/<Area>/<SliceName>.cs` for small ones). Namespace `Todo.Server.Features.<Area>.<SliceName>`.
- Static class named like the slice containing nested `Request`, `Response`, `Validator`, `Endpoint`, `Handler`.
- A slice never references a type from another slice (AT-01). Shared code for slices of one area goes in `Features/<Area>/_Shared`.
- Handler order: validate (filter) → load → authorize → entity method → side effects through writers → `SaveChangesAsync` once → map response.
- If a slice must use `ExecuteUpdateAsync` or `ExecuteDeleteAsync` (set-based SQL runs immediately), it wraps the whole handler body in `db.InTransactionAsync(...)` (Common) so the rule "one slice, one transaction" still holds.

## 4.3 Side-Effect Contract (replaces events)

Writers only **add rows to the caller's `DbContext`**. They never call `SaveChangesAsync`. The slice saves once, so state and side effects are atomic.

| Side effect | Call in the slice | Rows written |
| --- | --- | --- |
| History on a todo | `activity.Add(...)` | `todo_activities` |
| In-app notification (+ email if preferences allow) | `await notify.NotifyAsync(...)` | `notifications`, `email_deliveries` |
| One-time-link email (confirmation, reset, invitation) | `emailQueue.Enqueue(...)` | `email_deliveries` (encrypted payload) |
| Security or workspace audit | `audit.Security(...)` / `audit.Workspace(...)` | `security_audit_events`, `workspace_audit_events` |
| Reminder upkeep | `await reminders.OnTodoDueChangedAsync(...)` etc. | `reminders` |
| Cascade (workspace delete, member removal) | set-based SQL inside `InTransactionAsync` | several tables |

# 5. Reference Slice: CreateTodo (US-TODO-001)

Every new slice copies this shape. One file, everything nested.

```csharp
namespace Todo.Server.Features.Todos.CreateTodo;

public static class CreateTodo
{
    public sealed record Request(string? Title, string? Description, string? Priority,
        DateTimeOffset? DueAt, Guid? WorkspaceId, Guid? CategoryId);          // no owner field (AT-06)

    public sealed record Response(Guid Id, string Title, string Status, string Priority,
        DateTimeOffset? DueAt, Guid? WorkspaceId, DateTimeOffset CreatedAt);

    public sealed class Validator : AbstractValidator<Request>
    {
        public Validator()
        {
            RuleFor(x => x.Title).NotEmpty().Must(t => t!.Trim().Length is >= 1 and <= 200);
            RuleFor(x => x.Description).MaximumLength(10_000);
            RuleFor(x => x.Priority).Must(p => p is null || Enum.TryParse<TodoPriority>(p, false, out _));
            RuleFor(x => x.WorkspaceId).NotEqual(Guid.Empty).When(x => x.WorkspaceId.HasValue);
            RuleFor(x => x.CategoryId).NotEqual(Guid.Empty).When(x => x.CategoryId.HasValue);
        }
    }

    public sealed class Endpoint : IEndpoint
    {
        public void Map(IEndpointRouteBuilder app) =>
            app.MapPost("/api/v1/todos", async (Request r, Handler h, CancellationToken ct) =>
            {
                var result = await h.HandleAsync(r, ct);
                return result.IsSuccess ? Results.Created($"/api/v1/todos/{result.Value.Id}", result.Value) : result.Error.ToProblem();
            })
            .AddEndpointFilter<ValidationFilter<Request>>()
            .RequireAuthorization().WithName("CreateTodo").WithTags("Todos")
            .Produces<Response>(201).ProducesProblem(400).ProducesProblem(401).ProducesProblem(403).ProducesProblem(404).ProducesProblem(409);
    }

    internal sealed class Handler(AppDbContext db, ICurrentUser user, IWorkspaceAccess workspaces,
        IActivityWriter activity, TimeProvider clock)
    {
        public async Task<Result<Response>> HandleAsync(Request r, CancellationToken ct)
        {
            var userId = user.UserId;
            var priority = r.Priority is null ? TodoPriority.Medium : Enum.Parse<TodoPriority>(r.Priority);

            if (r.WorkspaceId is { } wsId)
            {
                var m = await workspaces.GetMembershipAsync(wsId, userId, ct);
                if (m is null || !m.IsActive) return Fail("not_found", ErrorKind.NotFound);               // Hidden -> 404
                if (m.WorkspaceStatus != WorkspaceStatus.Active) return Fail("workspace_archived", ErrorKind.Conflict);
                if (!workspaces.Has(m, WorkspacePermission.TodoCreate)) return Fail("permission_denied", ErrorKind.Forbidden);
            }

            if (r.CategoryId is { } catId)
            {
                // One database: a plain query. Personal todo: caller's own category. Workspace todo: the workspace's category.
                var ok = await db.Categories.AnyAsync(c => c.Id == catId &&
                    (r.WorkspaceId == null ? c.OwnerUserId == userId : c.WorkspaceId == r.WorkspaceId), ct);
                if (!ok) return Fail("invalid_category", ErrorKind.Validation);
            }

            var created = TodoItem.Create(Guid.CreateVersion7(), r.Title, r.Description, priority, r.DueAt,
                userId, r.WorkspaceId, r.CategoryId, clock.GetUtcNow());
            if (!created.IsSuccess) return Result<Response>.Fail(created.Error);
            var todo = created.Value;

            db.TodoItems.Add(todo);
            activity.Add(todo.Id, todo.WorkspaceId, userId, ActivityType.TodoCreated);
            await db.SaveChangesAsync(ct);                                  // todo + activity in one transaction

            return Result<Response>.Ok(new(todo.Id, todo.Title, todo.Status.ToString(), todo.Priority.ToString(),
                todo.DueAt, todo.WorkspaceId, todo.CreatedAt));
        }

        private static Result<Response> Fail(string code, ErrorKind kind) => Result<Response>.Fail(new(code, code, kind));
    }
}
```

The entity enforces the invariant; the database `CHECK` is the second line of defence:

```csharp
    public Guid Id { get; private set; }  public string Title { get; private set; } = default!;
    public Guid OwnerUserId { get; private set; }  public Guid? WorkspaceId { get; private set; }

    public DateTimeOffset? ArchivedAt { get; private set; }  public DateTimeOffset? DeletedAt { get; private set; }
```

# 6. Database Design

One database, one schema `app`, one migration history. Foreign keys are enforced. `ON DELETE` rules: `CASCADE` only for rows that are meaningless without their parent in the same aggregate (subtasks, comment revisions, tags on a deleted tag); everything else is `RESTRICT` (business data is soft-deleted) or `SET NULL` (optional references). Users are never hard-deleted except by the account-purge job, which first deletes or anonymises dependants.

## 6.9 Reporting Query Support

If a measured query exceeds its budget, the next steps in order are: covering index, materialised view refreshed by the worker, read replica.

## 9.3 Evaluation

Global roles are never consulted for workspace data (BR-WS-005). Single-todo checks use `ITodoAccess.GetAsync`; lists start from `VisibleTo`:

```csharp
public IQueryable<TodoItem> VisibleTo(IQueryable<TodoItem> q, Guid userId)
{
    var mine = db.WorkspaceMembers.Where(m => m.UserId == userId && m.Status == MemberStatus.Active
                                           && m.Workspace.Status != WorkspaceStatus.Deleted);
    return q.Where(t =>
        (t.WorkspaceId == null && t.OwnerUserId == userId)                                    // personal: owner only
     || mine.Any(m => m.WorkspaceId == t.WorkspaceId && m.Role != WorkspaceRole.Guest)       // workspace: all todos
     || mine.Any(m => m.WorkspaceId == t.WorkspaceId && m.Role == WorkspaceRole.Guest         // guest: assigned only
            && db.TodoAssignees.Any(a => a.TodoId == t.Id && a.AssigneeUserId == userId && a.UnassignedAt == null)));
}
```

Single-todo evaluation: deleted → Hidden (except restore); personal → owner Allowed else Hidden; workspace → no active membership or workspace deleted → Hidden; Guest not assigned → Hidden; edit = role has `TodoUpdate` and workspace Active and todo not archived, else Denied. Membership is cached per request only, so role changes and removals apply to the next request (US-MEM-007/008).

# 10. Slice Specifications

Each specification fixes route, validation, authorization, algorithm (with every side effect, all in **one transaction**), errors and minimum tests. Slices not listed in 10.1 to 10.12 follow the template in Section 5 and the rules in 10.13.

## 10.1 CompleteTodo, ReopenTodo, UpdateTodo (US-TODO-004/005/006)

**CompleteTodo** `POST /todos/{id}/complete`

1. Load `TodoItems` by id (query filter hides deleted). Not found → 404.
2. `access.GetAsync(todo, userId)`: `View != Allowed` → 404; `Edit != Allowed` → 403 (Guests cannot complete, TD-V2-06).
3. `todo.Complete(userId, now)`. Returns `false` → respond 200 with the current todo, **no side effects**.
4. Side effects: `activity.Add(TodoCompleted)`; `reminders.SkipForTodoAsync(todoId, "completed")`; if the todo has a recurrence rule with `AfterCompletion` policy and this is its latest occurrence, set the rule's `next_occurrence_utc` (calculator); for workspace todos, notify watchers except the actor (`TaskCompleted`, default email off).
5. `SaveChangesAsync` once. On `DbUpdateConcurrencyException` reload once: if now `Completed` return 200, else 409 `concurrency_conflict`.

- **Tests:** TC-COMPLETE-01 sets `completedAt` and one activity row; -02 second call writes nothing more; -03 two parallel calls give one activity row; -04 other user's personal todo 404; -05 workspace Member ok, Guest 403; -06 pending reminders become `Skipped`; -07 DB rejects `Completed` without timestamp (direct SQL).

**ReopenTodo:** `Completed → Pending`, clear `completed_at` and `completed_by_user_id`; `activity.Add(TodoReopened)`; `reminders.ReinstateForTodoAsync`; not completed → 200, no change (TD-V2-10). History stays in `todo_activities`.

**UpdateTodo** `PATCH /todos/{id}` + `If-Match`: JSON merge-patch; `status` may only move `Pending ↔ InProgress` (`Completed` → 400 `use_complete_endpoint`); archived todo → 409 `todo_archived`; category must be usable (same query as CreateTodo); due date change calls `reminders.OnTodoDueChangedAsync`; `activity.Add(TodoUpdated, changedFields)` only when something changed. Stale `If-Match` → 409.

## 10.2 GetTodos (US-TODO-002/010/011/012)

- **Base query:** `access.VisibleTo(db.TodoItems.AsNoTracking(), userId)`. `scope=personal` adds `WorkspaceId == null`; `scope=workspace` requires `workspaceId`, an active membership (else 404) and `TodoView`, and adds `WorkspaceId == ws`. Personal and workspace results are never mixed.
- **State:** `active` = not deleted and not archived; `archived`; `deleted` = caller's own deleted personal todos, or for Owner and Admin the workspace's, within 30 days (`IgnoreQueryFilters`, allow-listed by AT-07).
- **Filters:** status, priority, due range, `overdue` (`status <> Completed AND due_at < now`), `categoryId`, tags (`t.TodoTags.Any(x => tagIds.Contains(x.TagId))`, or `All` mode with a count), `assignedToMe` (`TodoAssignees.Any(...)`). All plain joins, no lookups across boundaries.
- **Search:** `q` (≤ 100 chars, trimmed, empty ignored) uses `to_tsvector('simple', ...) @@ websearch_to_tsquery('simple', q)`; with `q` and no `sort`, order by rank then `id` (TD-V2-07).
- **Sort:** allow-list; `dueAt` nulls last; priority order Urgent, High, Medium, Low; always `ThenBy(id)`.
- **Projection:** `Select` straight to `TodoListItem` including tag names and (workspace scope) assignee ids through correlated subqueries or one batched second query; no per-row calls.
- **Target:** p95 under 500 ms for 10,000 todos per user (proposed). The PR attaches `EXPLAIN` output for the personal and workspace paths.
- **Tests:** TC-GETTODOS-01 only own personal todos; -02 workspace todos not in personal scope; -03 deleted excluded; -04 deterministic pages; -05 `pageSize=101` is 400; -06 each filter alone and combined; -07 search never leaks others' rows; -08 Guest sees only assigned; -09 non-member 404; -10 tag `all` mode.

## 10.3 CreateWorkspace (US-WS-001)

Validate name (1–100) and description (≤ 1,000). Count owned active workspaces (limit 20, 409 `workspace_limit_reached`). Add `Workspace` (`Active`, default settings), `WorkspaceMember` (`Owner`, `Active`), `audit.Workspace(WorkspaceCreated)`. One save. Response 201 with `myRole = Owner`. `ux_wm_one_owner` and `Workspace.Create` guarantee BR-WS-001. Tests: creator is Owner; empty name 400; limit 409; audit row; duplicate names allowed (TD-V2-09).

## 10.4 ArchiveWorkspace and DeleteWorkspace (US-WS-004/005)

- **Archive** (Owner): `status = Archived`; in the same `InTransactionAsync` set all `Scheduled` reminders of the workspace to `Skipped` and pause its recurrence rules. Archived workspaces deny every mutating permission except delete.
- **Delete** (Owner, body `{confirmName}` equal to the workspace name else 400): one transaction runs

```sql
UPDATE app.workspaces SET status='Deleted', deleted_at=@now, updated_at=@now WHERE id=@ws;
UPDATE app.todo_items SET deleted_at=@now, deleted_by_user_id=@u WHERE workspace_id=@ws AND deleted_at IS NULL;
UPDATE app.reminders SET status='Cancelled', updated_at=@now WHERE workspace_id=@ws AND status IN ('Scheduled','Processing');
UPDATE app.recurrence_rules SET status='Ended', next_occurrence_utc=NULL WHERE workspace_id=@ws AND status<>'Ended';
UPDATE app.categories SET deleted_at=@now WHERE workspace_id=@ws AND deleted_at IS NULL;   -- and app.tags
UPDATE app.workspace_invitations SET status='Cancelled', resolved_at=@now WHERE workspace_id=@ws AND status='Pending';
```

plus an audit row. The workspace disappears from every list immediately and atomically. Physical purge by `RunRetentionCleanup` after the retention period. Test with a workspace of 50,000 todos for duration and lock impact (R-04).

## 10.5 InviteMember (US-MEM-001)

1. Validate: `email` RFC-valid ≤ 254, normalized (trim, NFKC, lower-case); `role` in Admin, Member, Guest (Owner → 400 `invalid_role`).
2. Authorize `MembersInvite`; Admin may invite Member and Guest only; workspace must be `Active`.
3. If an active member already has that email (join `asp_net_users` by normalized email) → 409 `duplicate_membership`. A pending invitation exists → 409 `invitation_already_pending`.
4. Create token: 32 random bytes, base64url. Store `SHA256(token)`. `expires_at = now + 7 days`.
5. Add the invitation row, `audit.Workspace(MemberInvited)`, and `emailQueue.Enqueue(workspace-invitation, model with the raw token, sensitive: true)`. One save, so the invitation and its email are atomic. The raw token exists only in the encrypted `protected_payload` and the email; it is nulled when delivery finishes.
6. Respond 201 with the `Invitation` (no token). Rate limit 20 invitations per hour per workspace.

- **Tests:** TC-INVITE-01 Admin invites Member; -02 Admin cannot invite Admin (403); -03 Member cannot invite; -04 duplicate pending 409; -05 existing member 409; -06 DB stores only the hash; -07 exactly one `email_deliveries` row; -08 non-member 404.

## 10.6 AcceptInvitation (US-MEM-002)

1. Caller must have a confirmed email (else 403 `email_not_confirmed`). Token from body.
2. Look up by `token_hash`. Not found → 404 `invitation_not_found`.
3. `Expired` or `expires_at <= now` → 410 `invitation_expired`; `Cancelled` or `Rejected` → 410 `invitation_unavailable`; `Accepted` by the same user → 200 (idempotent); accepted by another → 410.
4. Caller's normalized email must equal `email_normalized`, else 403 `email_mismatch`.
5. In one transaction: `UPDATE workspace_invitations SET status='Accepted', accepted_by_user_id=@u, accepted_at=now WHERE id=@id AND status='Pending' AND expires_at > now`. Zero rows means another request won: re-read and re-apply steps 3 and 4. Then add the `WorkspaceMember` with the invited role; a unique violation on `ux_wm_active` is treated as already a member.
6. Side effects: `audit.Workspace(InvitationAccepted)`; notify the Owner and Admins (`MemberJoined`). Return 200 `{ workspaceId }`.

- **Tests:** TC-ACCEPT-01 happy path; -02 expired 410; -03 cancelled 410; -04 wrong email 403; -05 ten parallel accepts create exactly one membership; -06 repeat by the same user returns 200 without a second notification; -07 unconfirmed email 403.

## 10.7 RemoveMember, LeaveWorkspace, ChangeMemberRole, TransferOwnership (US-MEM-007..009, US-WS-006)

- **RemoveMember** (`MembersManage`): cannot target the Owner (409 `final_owner`) or self. In one transaction: member `status = Removed`, `ended_at`, `removed_by_user_id`; then

```sql
UPDATE app.todo_assignees SET unassigned_at=@now, unassigned_by_user_id=@actor WHERE workspace_id=@ws AND assignee_user_id=@uid AND unassigned_at IS NULL;
DELETE FROM app.todo_watchers w USING app.todo_items t WHERE w.todo_id=t.id AND t.workspace_id=@ws AND w.user_id=@uid;
UPDATE app.reminders SET status='Cancelled' WHERE workspace_id=@ws AND recipient_user_id=@uid AND status IN ('Scheduled','Processing');
```

plus audit and a `MemberRemoved` notification to the removed user. Authored todos and comments remain (US-MEM-009). Effective on the next request because membership is read live.

- **LeaveWorkspace:** same statements with `status = Left`; Owner → 409 `owner_must_transfer`.
- **ChangeMemberRole:** cannot target the Owner or self; Admin cannot modify Admin; audit with old and new role; notify the member.
- **TransferOwnership:** target must be an active Admin or Member (409 `target_not_active_member`); in one transaction demote the old Owner row to `Admin` **first**, promote the target to `Owner`, set `workspaces.owner_user_id`, audit, notify both. Both unique indexes stay satisfied.
- **Tests:** TC-REMOVE-01 removed user gets 404 on workspace routes at once; -02 their todos remain; -03 assignments cleared and reminders cancelled in the same request; -04 Admin cannot remove Admin; -05 transfer leaves exactly one Owner; -06 Guest target refused.

## 10.8 AssignTodo and RemoveAssignee (US-COL-001/002)

1. `access.GetAsync`: not visible → 404. Personal todo → 400 `personal_todo_not_assignable`.
2. `WS:TodoAssign`; archived workspace → 409.
3. Assignee must be an active member (`WorkspaceMembers` query) else 409 `assignee_not_member`. Max 10 active assignees else 409 `too_many_assignees`.
4. Add `TodoAssignee` (the partial unique index maps a duplicate to 409 `already_assigned`), `activity.Add(TodoAssigned)`, and, unless assignee = actor, `notify.NotifyAsync(TaskAssigned, sourceKey: "assign:{todoId}:{userId}:{assignedAt.Ticks}")`. One save.

## 10.9 AddComment and related (US-COL-004..008)

## 10.10 Login and Identity flows (US-IAM-005, US-IAM-012)

1. Rate limit by IP and email. Normalize email, load user. Unknown email: hash a dummy password, return 401 `invalid_credentials`.
2. `status <> Active` → 401 `invalid_credentials` (reason only audited).
3. `CheckPasswordSignInAsync(lockoutOnFailure: true)`. Wrong → audit `LoginFailed`, 401. Locked out → audit `AccountLockedOut`, 403 `account_locked` + `Retry-After`.
4. Correct password and email unconfirmed → 403 `email_not_confirmed`.
5. `TwoFactorEnabled` → issue the partial two-factor cookie, respond `{status:'MfaRequired'}`; no session exists yet.
6. Otherwise add `UserSession`, sign in with claims `sub`, `sid`, `tz`, `amr`, audit `LoginSucceeded`, one save.

- **Tests:** TC-LOGIN-01 valid; -02 wrong password generic 401; -03 unknown email same response and latency band; -04 lockout after 5; -05 unconfirmed 403; -06 partial MFA state cannot call `/me`; -07 cookie flags; -08 disabled account cannot sign in; -09 revoked session rejected on next request.

Other Identity slices (register, confirm, reset, MFA, sessions, passkeys, delete account, admin) keep the behaviour of USAC and the v1 specification: tokens through `UserManager` and `ITokenProtector`, emails through `IEmailQueue`, audit through `IAuditWriter`, all in the slice transaction. ## 10.11 Categories and Tags (US-ORG-001..005)

- Name 1–50 trimmed; color `#RRGGBB`. Scope derived from `workspaceId` (none → Personal; present → Workspace, needs `OrganizationManage`). Case-insensitive duplicate in the same scope → 409 `duplicate_name`. Limits 100 categories and 200 tags per scope.
- Update needs `If-Match`; scope is immutable. **Delete category:** soft delete plus `UPDATE todo_items SET category_id = NULL WHERE category_id = @id` in the same transaction (todos are never deleted). **Delete tag:** soft delete and `DELETE FROM todo_tags WHERE tag_id = @id`.
- **AssignTag/RemoveTag:** todo edit permission; the tag's scope must match the todo (personal tag → the caller's personal todos; workspace tag → todos of that workspace) else 409 `tag_scope_mismatch`; max 20 tags per todo; idempotent.
- **Tests:** duplicate differing only by case; another user's category not usable; delete clears todo category; scope mismatch; 20-tag limit; Member cannot create workspace tag, Admin can.

## 10.12 Reporting (US-REP-001..005)

All slices start from `VisibleTo` or an explicit membership check; no projection tables.

```sql
SELECT count(*) AS total,
  count(*) FILTER (WHERE status = 'Completed')                    AS completed,
  count(*) FILTER (WHERE status <> 'Completed')                   AS pending,
  count(*) FILTER (WHERE status <> 'Completed' AND due_at < now()) AS overdue,
  count(*) FILTER (WHERE status <> 'Completed'
     AND (due_at AT TIME ZONE @tz)::date = (now() AT TIME ZONE @tz)::date) AS due_today,
  count(*) FILTER (WHERE completed_at >= date_trunc('week', now() AT TIME ZONE @tz) AT TIME ZONE @tz) AS completed_this_week
FROM app.todo_items
WHERE owner_user_id = @me AND workspace_id IS NULL AND deleted_at IS NULL AND archived_at IS NULL;
```

- **Dashboard `scope=all`** adds workspace todos assigned to the caller in workspaces where they are still an active member. **Trends:** `from`, `to` (max 366 days), day or week buckets in the caller's time zone; empty buckets are filled with zeros in code. **Workspace dashboard and member summary** need `ReportsView` and `ReportsMembers`; member counts group `todo_assignees` joined to `todo_items`, names from `asp_net_users`, members with no tasks included with zeros.
- **ExportTasks:** streams CSV from an `IAsyncEnumerable` (UTF-8 with BOM, RFC 4180). Cells starting with `=`, `+`, `-`, `@`, tab or CR are prefixed with `'`. Above 50,000 rows → 413 `export_too_large`. Columns: `Id, Title, Description, Status, Priority, DueAt, CompletedAt, CreatedAt, Workspace, Category, Tags, Assignees`.
- **Tests:** zeros for empty data; counts equal seeded rows; week boundary per time zone (`Asia/Ho_Chi_Minh`, `America/Los_Angeles`); Member without `ReportsView` 403; personal todos never counted in workspace totals; CSV injection prefix; 413.

## 10.13 Rules for Remaining Slices

| Slice group | Rules easy to miss |
| --- | --- |
| DeleteTodo, RestoreTodo | Soft delete sets `deleted_at`, `deleted_by_user_id`, calls `SkipForTodoAsync` and adds activity; restore only by deleter, owner or workspace Owner/Admin within 30 days (410 `retention_expired`), reinstates reminders. Delete of an already deleted todo is 204 |
| ArchiveTodo | Sets `archived_at`; independent of status; archived todos are read-only and excluded from active lists and reminders |
| Subtasks | Max 100; reorder body must contain exactly the parent's subtask ids (400 `ids_mismatch`), reassign `sort_order = 1024 * position` in one transaction; completing all subtasks does **not** complete the parent (TD-V2-11) |
| GetAssignedTodos | `todo_assignees` joined to `todo_items` through `VisibleTo`; paging on the joined query |
| WatchTodo | `PUT` insert with conflict ignore, `DELETE` removes; both 204; requires view access |
| GetTodoActivity | Same visibility as GetTodo; oldest first |
| Recurrence | Validation and calculation as Section 12.3; one live rule per template todo (409 `recurrence_exists`); changing the schedule recomputes `next_occurrence_utc` from now and never touches generated todos; stop is idempotent (`Pause` or `End`) |
| Reminders | Absolute needs a future time; `BeforeDue` needs a due date and a future computed time (400 `reminder_in_past`); another recipient requires `TodoAssign` and that user must be an assignee; max 10 per recipient; duplicates 409 `reminder_exists`; update only while `Scheduled`; delete is idempotent |
| Notifications API | Own rows only (foreign ids 404); `MarkAsRead` is `UPDATE ... WHERE recipient_user_id = @me`; preferences list contains every category with defaults merged; mandatory categories cannot be disabled (400 `mandatory_notification`) |
| DisableUser | Sets status, revokes all `user_sessions`, bumps the security stamp, audits; not self, not the last PlatformAdministrator (409 `admin_guard`) |

| Entity | Transitions |
| --- | --- |
| Todo | `(new) → Pending`; `Pending ↔ InProgress` (UpdateTodo); `Pending or InProgress → Completed` (CompleteTodo); `Completed → Pending` (ReopenTodo). Orthogonal flags: `archived_at`, `deleted_at` |
| Invitation | `(new) → Pending`; `Pending → Accepted, Rejected, Cancelled, Expired`; `Pending → Pending` on resend (new `token_hash`, new expiry; the old token stops working). Terminal states never move |
| Workspace | `Active → Archived → Deleted`; `Active → Deleted` |
| Member | `Active → Removed` or `Left` (terminal; re-joining adds a new row) |
| Reminder | `Scheduled → Processing → Sent`; `Scheduled or Processing → Cancelled`; `Scheduled → Skipped`; `Skipped → Scheduled` (reinstated); `Processing → Scheduled` when a lease expires; `Processing → Failed` after 5 attempts |
| Recurrence rule | `Active ↔ Paused`; `Active or Paused → Ended` (terminal) |
| Email delivery | `Queued → Sending → Sent`; `Sending → RetryScheduled → Sending`; `Sending → Failed`; `Queued → Suppressed` |

# 12. Background Slices

The worker role (`Hosting:Role` = `worker` or `all`) registers these hosted services. Each cycle catches exceptions per batch, logs with a correlation id and continues. All use the same claiming pattern, so several worker replicas are safe.

## 12.1 Claiming and Retry Pattern

```sql
WITH due AS (
  SELECT id FROM app.email_deliveries
  WHERE status IN ('Queued','RetryScheduled') AND next_attempt_at <= now()
    AND (claimed_until IS NULL OR claimed_until < now())
  ORDER BY next_attempt_at LIMIT @batch FOR UPDATE SKIP LOCKED)
UPDATE app.email_deliveries e
SET status = 'Sending', claimed_by = @worker, claimed_until = now() + interval '2 minutes', attempt_count = attempt_count + 1
FROM due WHERE e.id = due.id RETURNING e.*;
```

A crashed worker's rows become claimable again when the lease expires. The same pattern, with their own status columns, serves reminders and recurrence rules.

| Slice | Interval (proposed) | Batch | Work |
| --- | --- | --- | --- |
| ProcessEmailQueue | 5 s | 20 | Unprotect payload, render Scriban template (locale, fallback `en`), call `IEmailProvider.SendAsync(message, idempotencyKey: id)`. Transient errors (timeouts, 4xx throttling) → `RetryScheduled` after 1 min, 5 min, 15 min, 1 h, 3 h, 6 h; permanent errors or the 7th failure → `Failed` with metric and alert. On `Sent` or `Failed` set `protected_payload = NULL`. `last_error` holds a sanitized code, never body or links |
| ProcessReminders | 30 s | 100 | See 12.2 |
| GenerateRecurringTodos | 60 s | 50 rules | See 12.3 |
| ExpireInvitations | 15 min | 500 | `UPDATE ... SET status='Expired' WHERE status='Pending' AND expires_at <= now()` |
| RunRetentionCleanup | daily 02:00 UTC | bounded | Purge todos soft-deleted over 30 days ago (children first), expired sessions over 30 days old, completed account deletions after the grace period (delete or anonymise dependants), audit rows past the retention period |

Worker health: `/health/live`, `/health/ready` and the gauge `worker_last_cycle_timestamp{job}`; an alert fires when a job's last cycle is older than 5 times its interval.

## 12.2 ProcessReminders (US-SCH-005..007)

In one transaction per reminder: claim (`Scheduled → Processing`), then finalise with the guarded statement `UPDATE reminders SET status='Sent', processed_at=now() WHERE id=@id AND status='Processing'`. If it affects 0 rows, the reminder was cancelled or skipped meanwhile and **nothing is sent**; if 1 row, call `notify.NotifyAsync(ReminderDue, sourceKey: "reminder:{id}")` and save. `DeleteReminder` runs `UPDATE ... SET status='Cancelled' WHERE id=@id AND status IN ('Scheduled','Processing')` and commits before returning, so after the response no reminder can be sent. `IReminderScheduler` keeps rows consistent when todos change (due date moved, completed, deleted, restored, workspace archived or member removed). A reminder that would fall in the past becomes `Skipped`.

## 12.3 GenerateRecurringTodos (US-SCH-002)

**Occurrence calculation** (`RecurrenceCalculator`, NodaTime). Occurrence *n* (0-based) is computed from the rule start, not from the previous occurrence, so there is no drift.

| Frequency | Local date and time of occurrence *n* |
| --- | --- |
| Daily | `start_local + n * interval` days |
| Weekly | weeks stepping by `interval`; inside each week the sorted `by_weekdays`; occurrences before `start_local` skipped |
| Monthly | month `start + n * interval`; day = `by_month_day` or the start day; `-1` or a day beyond the month length is clamped to the last day |
| Yearly | `start_local + n * interval` years; 29 Feb in non-leap years becomes 28 Feb |

Conversion: `zone.ResolveLocal(local, Resolvers.LenientResolver)`. A non-existent local time (spring-forward gap) shifts forward by the gap; an ambiguous time (fall-back) resolves to the earlier instant. Golden tests cover `America/New_York`, `Europe/London`, `Australia/Lord_Howe` and `Asia/Ho_Chi_Minh`.

**Cycle, all in one database transaction per rule (one database, no cross-module coordination):**

1. Claim up to 50 rules with `status='Active' AND next_occurrence_utc <= now()` using `FOR UPDATE SKIP LOCKED` and a lease.
2. For each due occurrence number (at most 10 per rule per cycle; older than 30 days recorded as `Skipped`): insert the new `todo_items` row copying title, description, priority, category, workspace and owner from the template, with `recurrence_rule_id`, `occurrence_number` and due date = scheduled instant. The unique index `ux_todo_occurrence` makes a repeat impossible (on conflict the number is treated as already generated).
3. Insert `scheduled_occurrences`, increment `occurrences_generated`, set the next `next_occurrence_utc`, or `status = 'Ended'` when `max_occurrences` or `ends_on_local` is reached.
4. An error on a rule is stored in `last_error`, counted in `recurrence_failures_total`, and retried with backoff; other rules continue.

Assignees and reminders are **not** copied to generated todos in the first release (TD-V2-13). `generation_policy = AfterCompletion` leaves `next_occurrence_utc` empty after generating and sets it from `CompleteTodo` (Section 10.1).

| --- | --- | --- | --- |

| RemoveAssignee | the former assignee | TaskUnassigned | off |

## 13.1 Structure


## 13.2 Routes

| Path | Page | Guard |
| --- | --- | --- |
| `/login`, `/register`, `/forgot-password`, `/reset-password`, `/confirm-email`, `/login/mfa` | Auth pages | `guestOnly` |
| `/invitations/accept` | Reads the token from `location.hash`, removes it with `history.replaceState`, posts it | login with `returnUrl` first |
| `/todos`, `/todos/:id` | Personal todos | `requiresAuth` |

| `/admin/users`, `/admin/audit` | Administration | `requiresRole` |

Route guards only improve navigation; the server authorizes every call.

## 13.3 API Client and State

- Types and operations are generated from the OpenAPI document (`openapi-typescript`, `openapi-fetch`); CI fails when committed types are stale.
- One fetch wrapper sets `credentials: 'include'` and `X-XSRF-TOKEN` (loaded from `GET /auth/antiforgery`, refreshed after login and logout). Problem Details become `ApiError { status, code, detail, errors, correlationId }`; components branch on `code`.
- Global handling: 401 → clear cache and go to `/login?returnUrl=` (except the initial `GET /me` probe); 403 → permission message; 409 `concurrency_conflict` → refetch and tell the user the item changed; 429 → honour `Retry-After`; 500 → generic message with `correlationId`.
- ETags from `GET` are kept in query data and sent as `If-Match` on updates.
- Query keys: `['me']`, `['todos','list',scope,filters]`, `['todos','detail',id]`, `['workspaces']`, `['workspace',id,'me']`, `['workspace',id,'members']`, `['todo',id,'comments']`, `['notifications','unread']` (polled every 30 s while the tab is visible), `['dashboard',scope]` (stale time 30 s). A mutation invalidates the keys of the data it changed.
- Pinia holds only the active workspace id (validated against `['workspaces']`), UI preferences and navigation state.
- Forms: `vee-validate` with `zod`; server `errors` map to fields. Completing a todo is optimistic with rollback; other mutations wait for the server.
- Every view has loading, error-with-retry and empty states; destructive actions use a confirmation dialog (deleting a workspace requires typing its name); accessibility per NFR-UX (semantic HTML, focus management, keyboard use, `axe-core` in Playwright). User text is rendered as text, never HTML. Dates show in the user's `timeZoneId`; instants are sent as UTC ISO strings.

## 14.1 Minimum Tests per Slice

| Layer | Requirement |
| --- | --- |
| Slice integration | `WebApplicationFactory` and real PostgreSQL (Testcontainers; schema from migrations; Respawn reset). Happy path, one test per error code of the slice, authorization rows (allowed role, denied role, non-member 404, anonymous 401) |
| Persistence and side effects | Assert the stored row (UTC time, owner from the session) **and each side-effect row** (activity, notification, email queue, audit, reminder changes) in the same request |
| Entity unit | Every invariant and illegal transition in `Domain/` |
| Validator unit | One test per rule with boundary values |
| Contract | OpenAPI snapshot; a breaking change (oasdiff) fails CI |

## 14.2 Infrastructure

`FakeTimeProvider` in the test host; `Client.AsUser(userId, roles)` issues a real cookie, `AsAnonymous()` for 401; `CapturingEmailProvider` records messages and tests read links from it; `WorkerHarness.RunOnceAsync<TJob>()` runs one cycle deterministically; builders (`TodoBuilder`, `WorkspaceBuilder`) seed through entities or slices, raw SQL only in constraint tests.

## 14.3 Architecture Tests (AT-01..AT-09, every build)

AT-01 slice isolation (no reference to another slice; same-area `_Shared` allowed). AT-02 `Common`, `Domain`, `Services`, `Infrastructure` never reference `Features`. AT-03 `Domain` references no EF Core, ASP.NET Core or Infrastructure. AT-04 every endpoint declares authorization. AT-05 no `DateTime.UtcNow`, `DateTime.Now`, `DateTimeOffset.UtcNow`. AT-06 no identity fields in `Request` records. AT-07 `IgnoreQueryFilters` only in allow-listed slices. AT-08 entities have no public setters. AT-09 DI container validates with no constructor cycles.

## 14.4 Security, Concurrency and Time

- **IDOR sweep (generated from OpenAPI):** two users, two workspaces; every route with id parameters is called with the other party's ids and must return 404 (or 403 only where Section 7 says the resource is visible). A new route without coverage fails the sweep.
- **Matrix tests:** Section 9.2 encoded as data, one parametrised test per permission and role. A PlatformAdministrator who is not a member gets 404 on workspace data.
- **Sessions and CSRF:** revoked session rejected on the next request; password change and disable invalidate sessions; every state-changing route returns 400 without `X-XSRF-TOKEN`; rate limits return 429 with `Retry-After`.
- **Secrets:** a log-capture test asserts that passwords, tokens and recovery codes never appear in logs or audit data. **Enumeration:** login, forgot-password and resend-confirmation responses are identical for existing and unknown emails.
- **Concurrency:** two parallel `PATCH` with one ETag give one success and one 409; double `complete` writes one activity row; ten parallel `accept` calls give one membership; two workers over the same data process each reminder, occurrence and email once; kill the worker mid-cycle and the next run completes without duplicates.
- **Time:** DST golden tables (Section 12.3), month-end clamping, leap-day yearly rule, week boundaries for `Asia/Ho_Chi_Minh` and `America/Los_Angeles`.

# Appendix A. Developer Guide (all levels)

## A.1 Twelve Steps to Add a Slice

1. Read the story, its acceptance criteria and the slice row in Section 7 or 10.
2. Create `Features/<Area>/<SliceName>/<SliceName>.cs` with the static class and nested `Request`, `Response`, `Validator`, `Endpoint`, `Handler` (copy Section 5).
3. Request and response are records; no identity fields in requests.
4. Validator checks shape and range only; add one unit test per rule.
5. If a rule must always hold, add or extend an entity method in `Domain/` and unit-test it, including the illegal case.
6. Handler order: load, authorize through `ITodoAccess` or `IWorkspaceAccess`, entity method, side effects through writers, `SaveChangesAsync` once, map.
7. Endpoint: route, `AddEndpointFilter<ValidationFilter<Request>>()`, `RequireAuthorization()` (or explicit `AllowAnonymous()`), `Produces` for every status in the error table.
8. Schema change: EF configuration and migration (`dotnet ef migrations add Name --project src/Todo.Server`), check against Section 6.
9. Write slice integration tests (Section 14.1).
10. Export OpenAPI, commit the snapshot, regenerate frontend types.
11. Build the frontend action folder (api, hook, component, schema).
12. Tick the Definition of Done (Section 15.3).

## A.2 Where Does This Code Go?

| I need to | Put it in | Never in |
| --- | --- | --- |
| Check a length or format | the slice's `Validator` | the handler |
| Enforce an invariant (a completed todo has a time) | entity method and DB `CHECK` | handler `if` chains |
| Check whether a user may see or change something | `ITodoAccess`, `IWorkspaceAccess` | a hand-written query in the slice |
| Write a notification, activity, audit or email | the shared writer | direct inserts in every slice |
| Reuse logic between two slices | duplicate once; at the third use move it (area `_Shared`, `Services/`, `Domain/`, `Common/`) | calling the other slice |
| Get the time or the user | `TimeProvider`, `ICurrentUser` | `DateTime.UtcNow`, request body |

## A.3 Cookbook

**Concurrency conflict on a state transition:**

```csharp
try { await db.SaveChangesAsync(ct); }
catch (DbUpdateConcurrencyException)
{
    db.ChangeTracker.Clear();
    var fresh = await db.TodoItems.AsNoTracking().FirstAsync(t => t.Id == id, ct);
    return fresh.Status == TodoStatus.Completed ? Result<Response>.Ok(Map(fresh))     // someone else did it: idempotent success
        : Result<Response>.Fail(new("concurrency_conflict", "The item changed. Reload and retry.", ErrorKind.Conflict));
}
```

**`If-Match` on update:** `db.Entry(todo).Property(x => x.Version).OriginalValue = expected;` makes EF add `WHERE xmin = @expected` to the UPDATE.

**Set-based SQL inside one transaction:**

```csharp
return await db.InTransactionAsync(async () =>
{
    var rows = await db.Database.ExecuteSqlInterpolatedAsync($"UPDATE app.reminders SET status='Cancelled' WHERE workspace_id={ws} AND status IN ('Scheduled','Processing')", ct);
    audit.Workspace(wsId, WorkspaceAuditType.WorkspaceDeleted, user.UserId, null);
    await db.SaveChangesAsync(ct);
    return Result<Response>.Ok(new());
}, ct);
```

**Paging helper (Common):** `ToPagedAsync(PageRequest p, ct)` runs `CountAsync` then `Skip/Take`; the caller already applied a deterministic `OrderBy(..., ThenBy Id)`.

## A.4 Pitfalls Checklist for Reviewers

1. A request contains `UserId`, `OwnerUserId` or `AuthorUserId`.
2. A query on user data does not start from `VisibleTo` or a membership check.
3. 403 returned where the resource should be invisible (404).
4. A slice references another slice's types.
5. `SaveChangesAsync` called twice in one handler, or `ExecuteUpdate` used outside `InTransactionAsync`.
6. A writer is used and the slice forgets to save, or the writer saves by itself.
7. `DateTime.Now` or `UtcNow` used.
8. Enum stored as integer or status typed as a string literal.
9. List without a deterministic `OrderBy ... ThenBy(id)` or without a `pageSize` maximum.
10. N+1 queries (a query inside a loop).
11. Password, token, recovery code, email body or comment text in logs or audit `data`.
12. Business rule only in the frontend or only in a validator.
13. `IgnoreQueryFilters()` without a reason and without allow-listing.
14. Missing `Produces` metadata so the OpenAPI snapshot is incomplete.
15. New route not covered by the IDOR sweep or the role-matrix test.
16. Migration that drops or renames a column in the same release as the code that stops using it.
17. Time zone logic with `TimeZoneInfo` (use NodaTime and IANA ids).
18. Error message that reveals whether an email, token or id exists.
19. Shared service growing a method used by one slice only.
20. `catch (Exception)` that hides an error and returns success.

# Appendix B. Registries and Setup

## B.1 Error Code Registry

Codes are stable API; adding is allowed, renaming or removing is a breaking change. The frontend maps each code to a message in `shared/api/errorMessages.ts`.

| Code | HTTP | Meaning |
| --- | --- | --- |
| `validation_failed` | 400 | Field-level validation failed (`errors` lists fields) |
| `invalid_sort_field`, `invalid_role`, `invalid_category`, `invalid_mention`, `invalid_time_zone`, `unsupported_locale`, `invalid_phone`, `ids_mismatch`, `confirmation_mismatch`, `scope_immutable`, `mandatory_notification`, `reminder_in_past`, `use_complete_endpoint`, `personal_todo_not_assignable` | 400 | Specific request problems |
| `if_match_required`, `antiforgery_invalid`, `token_invalid`, `invalid_code`, `invalid_current_password` | 400 or 401 | Missing or wrong precondition, token or code |
| `unauthenticated`, `invalid_credentials`, `mfa_session_expired`, `session_revoked` | 401 | Not signed in or session invalid |
| `permission_denied`, `account_locked`, `email_not_confirmed`, `email_mismatch`, `mfa_required_for_role` | 403 | Visible but not allowed, or account state forbids it |
| `not_found`, `invitation_not_found` | 404 | Missing, deleted or hidden |
| `concurrency_conflict`, `invalid_state_transition`, `todo_archived`, `workspace_archived`, `not_deleted`, `not_pending`, `reminder_not_scheduled` | 409 | State conflicts |
| `email_already_registered`, `duplicate_membership`, `invitation_already_pending`, `already_assigned`, `duplicate_name`, `recurrence_exists`, `reminder_exists`, `external_login_in_use` | 409 | Duplicates |
| `final_owner`, `owner_must_transfer`, `owns_workspaces`, `last_login_method`, `admin_guard`, `target_not_active_member`, `assignee_not_member`, `tag_scope_mismatch` | 409 | Business-rule protections |
| `too_many_subtasks`, `too_many_assignees`, `too_many_tags`, `too_many_reminders`, `workspace_limit_reached` | 409 | Limits |
| `invitation_expired`, `invitation_unavailable`, `token_expired`, `retention_expired` | 410 | Time-limited resource no longer available |
| `export_too_large` | 413 | CSV above 50,000 rows |
| `rate_limited` | 429 | Too many requests (`Retry-After`) |
| `internal_error` | 500 | Unexpected; generic message with `correlationId` |

## B.3 Observability Names

Logs carry `CorrelationId`, hashed `UserId`, `Feature`, `Slice` (never emails, tokens or bodies). One span per handler named `slice.<Area>.<Slice>`. Counters: `todo_created_total`, `todo_completed_total`, `workspace_created_total`, `invitation_accepted_total`, `login_failed_total{reason}`, `account_lockout_total`, `email_sent_total`, `email_failed_total`, `recurrence_failures_total`, `reminders_sent_total`. Gauges: `email_queue_pending_age_seconds`, `reminders_overdue_count`, `worker_last_cycle_timestamp{job}`. Health: `/health/live`, `/health/ready`.

## B.4 Local Setup

1. Install .NET SDK 10, Node.js LTS, Docker.
2. `docker compose up -d db mail` (PostgreSQL and a local SMTP catcher).
3. `dotnet run --project src/Todo.Server -- --migrate` applies migrations.
4. `Hosting__Role=all dotnet run --project src/Todo.Server` runs API and worker together.
5. `npm install && npm run dev` in `web` (the dev server proxies `/api` so cookies stay same-site).
6. `dotnet test` (Testcontainers needs Docker), `npm run test`, `npm run e2e`.
7. `dotnet run --project src/Todo.Server -- --seed` creates demo users, one workspace per role and sample todos (Development only).

A new developer should have a running system with a registered, confirmed user within 30 minutes (US-PLAT-001).
