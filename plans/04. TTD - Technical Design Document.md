# 1. Introduction

## 1.1 Purpose

This document is the fourth in the delivery chain:

```text
SRD (what the business needs)
  → SAD (how the system is structured)
    → USAC (what each story must do)
      → TDD (exactly how each slice, API and table is built)   ← this document
```

It defines the implementable contracts that developers and QA build against:

- Technical conventions shared by every module.
- Building blocks and the vertical-slice implementation pattern.
- Public module contracts (interfaces and integration events).
- Physical database design per module.
- REST API catalogue and core resource schemas.
- Detailed specifications of the critical vertical slices.
- State machines, authorization matrix, background-job algorithms.
- Frontend technical design, test design and slice-level traceability.

# 2. Technical Conventions

## 2.1 Identifiers, Time and Enumerations

| Topic | Convention |
| --- | --- |
| Primary keys | `uuid`, generated in application code with `Guid.CreateVersion7()` (time-ordered, index-friendly). Never generated by the client. |
| Timestamps | `timestamptz`, always UTC (ASM-011). Mapped to `DateTimeOffset` with zero offset. Property names end in `At` (`CreatedAt`, `DueAt`). |
| Local date/time | Only for recurrence rules: `timestamp without time zone` plus an IANA `time_zone_id` (ASM-012). |
| Time source | All code uses `TimeProvider` (registered once in BuildingBlocks). `DateTime.UtcNow` is forbidden by an architecture test. |
| Time zones | IANA identifiers (`Asia/Ho_Chi_Minh`). Validated against NodaTime TZDB. Default `UTC`. |
| Enumerations | Stored as `text` with a `CHECK` constraint. Serialized as PascalCase strings in JSON. Never stored or sent as integers. |
| Strings | `text` columns with explicit `CHECK (char_length(col) <= N)`. Request validators enforce the same limit. |
| Soft delete | Nullable `deleted_at`. Global EF query filter excludes soft-deleted rows. Admin and restore slices call `IgnoreQueryFilters()` explicitly. |
| Naming mapping | EF Core with snake\_case naming convention. One schema per module (SAD §7.1). |

## 2.3 Pagination Contract

All collection endpoints use offset pagination (NFR-PER-001):

```text
GET /api/v1/todos?page=1&pageSize=25&sort=dueAt&direction=asc
```

| Parameter | Default | Rule |
| --- | --- | --- |
| `page` | 1 | integer ≥ 1 |
| `pageSize` | 25 | 1–100. Values above 100 are rejected with 400 (not silently clamped). |
| `sort` | endpoint-specific | Must be in the endpoint's documented allow-list, otherwise 400 `invalid_sort_field`. |
| `direction` | `asc` | `asc` or `desc`. |

Response envelope:

```json
{
  "items": [],
  "page": 1,
  "pageSize": 25,
  "totalCount": 137,
  "totalPages": 6
}
```

Every sort has a deterministic tiebreaker (`id`) so pages never overlap. Activity feeds and notifications MAY switch to keyset pagination (`cursor`) later if offset cost grows; the envelope would then add `nextCursor`.

## 2.3.1 Error Contract (US-PLAT-003)

All errors use RFC 9457 Problem Details with `application/problem+json`:

```json
{
  "type": "validation-error",
  "title": "Validation failed",
  "status": 400,
  "code": "validation_failed",
  "detail": "The request contains invalid fields.",
  "correlationId": "0HN7F2K3…",
  "errors": {
    "title": ["Title is required."]
  }
}
```

| Field | Rule |
| --- | --- |
| `type` | Stable kebab-case slug equal to the error kind (`validation-error`, `not-found`, `conflict`, …) as in SAD §10.3. |
| `code` | Stable machine-readable snake\_case code. The frontend switches on `code`, never on `detail`. |
| `detail` | Human-readable, safe to display, never contains stack traces, SQL or internal identifiers. |
| `correlationId` | The W3C trace ID of the request. Also returned in the `X-Correlation-Id` header. |
| `errors` | Only for 400 validation errors: field name (camelCase) → array of messages. |

### Error kind → HTTP status mapping

| ErrorKind | HTTP | Typical codes |
| --- | --- | --- |
| Validation | 400 | `validation_failed`, `invalid_sort_field`, `filter_too_broad` |
| Unauthenticated | 401 | `unauthenticated`, `mfa_required`, `session_revoked` |
| Forbidden | 403 | `permission_denied`, `account_locked`, `email_not_confirmed` |
| NotFound | 404 | `not_found` (also used when the caller may not know the resource exists) |
| Conflict | 409 | `concurrency_conflict`, `invalid_state_transition`, `duplicate_membership`, `email_already_registered` |
| Gone | 410 | `invitation_expired`, `token_expired` |
| PayloadTooLarge | 413 | `export_too_large` |
| RateLimited | 429 | `rate_limited` (with `Retry-After`) |
| Unexpected | 500 | `internal_error` |

**Disclosure rule (AUTHZ-007, BR-TODO-002):** if the caller is not allowed to know a resource exists (someone else's personal todo, a workspace they are not a member of), the API returns **404**. If the caller can see the resource but lacks the permission for the operation (a Member trying to delete a workspace), the API returns **403**. Slices obtain this behaviour from `AccessDecision` (Section 3.4), not by ad-hoc checks.

## 2.4 Optimistic Concurrency

- Mutable aggregates (`TodoItem`, `Workspace`, `RecurrenceRule`, `Reminder`, `Category`, `Tag`) expose a `Version`.
- `Version` is mapped to the PostgreSQL system column `xmin` (`IsRowVersion()` with Npgsql). No extra column is required.
- The API returns it as a weak ETag: `ETag: W/"123456"`.
- `PATCH`/`PUT` update operations MUST send `If-Match`. Missing header → 400 `if_match_required`. Stale value → 409 `concurrency_conflict`.
- State-transition operations (`complete`, `reopen`, `archive`, …) do not require `If-Match`; they are idempotent by design (Section 10).

## 2.5 Idempotency

| Operation type | Strategy |
| --- | --- |
| State transitions (`complete`, `cancel`, `revoke`) | Repeating the call on a target already in the final state returns 200/204 without a second event. |
| Event consumers | `inbox_messages` unique `(consumer, message_id)` (Section 5.9). |
| Recurrence generation | Unique `(recurrence_rule_id, occurrence_number)` in Todos and Scheduling (Section 12.3). |
| Invitation acceptance | Single `UPDATE … WHERE status = 'Pending'`; affected rows = 0 means already processed. |
| Client-driven creates (optional) | `Idempotency-Key` header on `POST /todos` and `POST /workspaces`; stored 24 h in `shared.idempotency_keys` (BuildingBlocks). SHOULD for R1, MAY be deferred. |

# 3. Solution Implementation Patterns

## 3.1 Building Blocks (`Todo.BuildingBlocks`)

BuildingBlocks contains technical abstractions only (SAD §15.1). It MUST NOT reference any module.

| Namespace | Contents |
| --- | --- |
| `Results` | `Result`, `Result<T>`, `Error`, `ErrorKind`, `AccessDecision` |
| `Security` | `ICurrentUser`, `CurrentUserAccessor`, `AuthorizationPolicies` |
| `Messaging` | `IIntegrationEvent`, `IIntegrationEventHandler<T>`, `OutboxMessage`, `InboxMessage`, `IOutboxWriter`, `IntegrationEventRegistry` |
| `Persistence` | `ModuleDbContext` base, `IUnitOfWork`, EF interceptors (audit timestamps, outbox capture), concurrency helpers |
| `Endpoints` | `IEndpoint`, `EndpointRegistration`, `ProblemDetailsMapper` |
| `Observability` | Activity sources, metrics, log enrichers (correlation ID) |
| `Time` | `TimeProvider` registration, NodaTime helpers |
| `Paging` | `PageRequest`, `PagedResult<T>` |

## 3.2 Result and Error Types

```csharp
public enum ErrorKind { Validation, Unauthenticated, Forbidden, NotFound, Conflict, Gone, PayloadTooLarge, RateLimited, Unexpected }

public sealed record Error(string Code, string Detail, ErrorKind Kind,
    IReadOnlyDictionary<string, string[]>? FieldErrors = null);

public readonly struct Result<T>
{
    public bool IsSuccess { get; }
    public T Value { get; }          // valid only when IsSuccess
    public Error Error { get; }      // valid only when !IsSuccess
    public static Result<T> Ok(T value);
    public static Result<T> Fail(Error error);
}
```

Handlers return `Result<T>`; they do not throw for expected business outcomes. Unexpected exceptions are handled by the global exception middleware (500, `internal_error`, logged with correlation ID).

## 3.3 Current User

```csharp
public interface ICurrentUser
{
    bool IsAuthenticated { get; }
    Guid UserId { get; }                       // throws if unauthenticated
    Guid? SessionId { get; }                   // from the 'sid' claim
    IReadOnlySet<string> GlobalRoles { get; }  // PlatformAdministrator, SupportAdministrator, StandardUser
    bool HasMfa { get; }                       // amr claim contains 'mfa'
    string TimeZoneId { get; }                 // from claim 'tz', default UTC
}
```

Rule (US-TODO-001, US-COL-004): the owner/author of any created record always comes from `ICurrentUser.UserId`, never from the request body. Architecture test `NoUserIdInRequests` fails the build if a `*Request` type has a property named `OwnerUserId`, `AuthorUserId` or `CreatedByUserId`.

## 3.4 AccessDecision

Authorization services return a three-state decision so slices can apply the disclosure rule consistently:

```csharp
public enum AccessDecision { Allowed, Hidden, Denied }
// Hidden  → caller may not know the resource exists → 404
// Denied  → caller can see it but lacks permission  → 403
```

`AccessDecision.ToError()` is the only place that maps decisions to HTTP errors.

## 3.5 Slice Template

Every feature folder follows this contract (SAD §6). Files are only created when needed.

```text
Features/CompleteTodo/
├── Request.cs        // record; route/query/body binding model
├── Validator.cs      // FluentValidation; shape and range only
├── Handler.cs        // orchestrates domain, persistence, outbox
├── Response.cs       // record
└── Endpoint.cs       // IEndpoint: route, auth, binding, status mapping
```

```csharp
public sealed class CompleteTodoEndpoint : IEndpoint
{
    public void Map(IEndpointRouteBuilder app) =>
        app.MapPost("/api/v1/todos/{id:guid}/complete",
            async (Guid id, CompleteTodoHandler handler, CancellationToken ct) =>
                (await handler.HandleAsync(new CompleteTodoRequest(id), ct)).ToHttp())
           .RequireAuthorization()
           .WithName("CompleteTodo")
           .WithTags("Todos")
           .Produces<CompleteTodoResponse>(200)
           .ProducesProblem(404).ProducesProblem(409);
}

public sealed class CompleteTodoHandler(
    TodosDbContext db, ICurrentUser user, ITodoAuthorizer authz,
    TimeProvider clock, IOutboxWriter<TodosDbContext> outbox)
{
    public async Task<Result<CompleteTodoResponse>> HandleAsync(
        CompleteTodoRequest request, CancellationToken ct) { /* Section 9 */ }
}
```

Handler order of operations (mandatory):

1. Load aggregate (tracked) via module `DbContext`.
2. Authorize via the module's authorizer (`AccessDecision`).
3. Call the domain method; the aggregate enforces invariants and returns a `Result`.
4. Add outbox message(s) in the same `DbContext` and call `SaveChangesAsync` once.
5. Map to response.

Handlers MUST NOT call another module's `DbContext`. Cross-module calls go through `*.Contracts` interfaces (Section 4).

## 3.6 Module Registration

Each module exposes exactly one public registration surface, called from `Todo.Api` and `Todo.Worker`:

```csharp
public static class TodosModule
{
    public static IServiceCollection AddTodosModule(this IServiceCollection s, IConfiguration c);
    public static IEndpointRouteBuilder MapTodosEndpoints(this IEndpointRouteBuilder app);
    public static IReadOnlyCollection<IOutboxSource> OutboxSources(IServiceProvider sp);
}
```

The worker host registers the same modules but maps no endpoints.

# 4. Module Contracts and Dependencies

## 4.1 Contracts Projects (refinement of SAD §5.2, see TD-002)

To avoid assembly cycles between modules that need each other's interfaces, each module splits its public surface into a separate, tiny project:

```text
Modules/Todos/
├── Todo.Modules.Todos/             // implementation, internal by default
└── Todo.Modules.Todos.Contracts/   // public interfaces, DTOs, integration events
```

Rules enforced by architecture tests:

- A module project may reference only its own `.Contracts`, other modules' `.Contracts`, and BuildingBlocks.
- `*.Contracts` projects reference only BuildingBlocks and the BCL. They contain no EF Core types, no entities and no `IQueryable`.
- Everything in an implementation project is `internal` except `{Module}Module`.

## 4.2 Allowed Dependency Graph (contracts only)

| Consumer module | May call contracts of |
| --- | --- |
| Todos | Workspaces, Collaboration, Organization, Identity |
| Workspaces | Identity |
| Collaboration | Todos, Workspaces, Identity |
| Organization | Todos, Workspaces |
| Scheduling | Todos, Workspaces |
| Notifications | Identity, Workspaces, Scheduling |
| Reporting | Workspaces (membership queries only) |
| Identity | Notifications (secure email queue only) |

Mutual dependencies (for example Todos ↔ Collaboration) are legal because only `.Contracts` assemblies are referenced; implementations are wired by DI. Constructor-level DI cycles are forbidden and covered by a startup validation test.

# 5. Database Design

One PostgreSQL database `todo_app`, one schema per module (SAD ADR-011), one `DbContext` and one migration history table per module (`__EFMigrationsHistory` in the module schema). No foreign keys cross schemas (SAD §7.10). Cross-module references are scalar `uuid` columns validated through contracts.

## 5.1 Common Columns and Rules

| Rule | Detail |
| --- | --- |
| Audit columns | `created_at timestamptz NOT NULL`, `updated_at timestamptz NOT NULL` set by an EF interceptor from `TimeProvider`. |
| Soft delete | `deleted_at timestamptz NULL` where the story requires recovery (todos, comments, workspaces). |
| Concurrency | `xmin` (no column declared in DDL). |
| Index naming | `ix_{table}_{columns}`; unique: `ux_{table}_{columns}`; check: `ck_{table}_{rule}`. |
| Partial indexes | Used for soft-deleted and status-filtered queries (`WHERE deleted_at IS NULL`). |
| Case-insensitive uniqueness | Unique index on `lower(name)`; no `citext` extension is required. |
| Migrations | Generated per module; applied by the migration job (SAD §16.3), never at API startup. Destructive changes follow expand → migrate → contract across two releases (NFR-REL-007). |

## 5.2 Identity Schema (`identity`)

Standard ASP.NET Core Identity tables are created by the framework store configuration in this schema (`asp_net_users`, `asp_net_roles`, `asp_net_user_roles`, `asp_net_user_claims`, `asp_net_role_claims`, `asp_net_user_logins`, `asp_net_user_tokens`, plus the passkey table provided by Identity). They are not redefined here.

### ApplicationUser extension columns

| Column | Type | Rule |
| --- | --- | --- |
| `display_name` | text | NOT NULL, 1–100 |
| `avatar_url` | text | NULL, ≤ 500 (object storage URL, optional) |
| `time_zone_id` | text | NOT NULL, default `'UTC'`, validated IANA id (FR-IAM-074) |
| `locale` | text | NOT NULL, default `'en'` (FR-IAM-073) |
| `status` | text | `Active` \| `Disabled` \| `PendingDeletion`; CHECK |
| `disabled_at`, `disabled_reason`, `disabled_by_user_id` | timestamptz / text / uuid | set by DisableUser (US-ADM-002) |
| `deletion_requested_at` | timestamptz | NULL; account deletion grace period (TD-012) |
| `created_at`, `updated_at` | timestamptz | NOT NULL |

`status <> 'Active'` blocks sign-in in `SignInManager` pre-checks (BR-IAM-005). Roles seeded: `PlatformAdministrator`, `SupportAdministrator`, `StandardUser`.

### `identity.user_sessions` (FR-IAM-080..082, SAD §9.6)

| Column | Type | Rule |
| --- | --- | --- |
| `id` | uuid | PK; value of the `sid` claim |
| `user_id` | uuid | NOT NULL; index |
| `created_at`, `last_seen_at`, `expires_at` | timestamptz | NOT NULL |
| `revoked_at` | timestamptz | NULL |
| `revoked_reason` | text | `UserLogout`, `UserRevoked`, `PasswordChanged`, `AdminDisabled`, `Compromise` |
| `ip_address` | inet | NULL (informational) |
| `user_agent` | text | NULL, ≤ 400 (informational only, never identity) |
| `is_persistent` | boolean | NOT NULL |

Index: `ix_user_sessions_user_id_active` on `(user_id) WHERE revoked_at IS NULL`.

Validation: the cookie `OnValidatePrincipal` event checks the `sid` row (memory-cached 30 s) and the Identity security stamp. `last_seen_at` is updated at most once per 5 minutes per session.

### `identity.security_audit_events` (FR-AUD-001/002/005, US-AUD-001)

| Column | Type | Rule |
| --- | --- | --- |
| `id` | uuid | PK |
| `occurred_at` | timestamptz | NOT NULL |
| `event_type` | text | NOT NULL, from catalogue below |
| `actor_user_id` | uuid | NULL (anonymous failures) |
| `subject_user_id` | uuid | NULL |
| `ip_address` | inet | NULL |
| `correlation_id` | text | NULL |
| `data` | jsonb | NOT NULL default `'{}'`; allow-listed keys only, never secrets (NFR-SEC-005) |

Insert-only: the application database role has `INSERT, SELECT` but no `UPDATE/DELETE` on this table. Retention purge runs under a separate maintenance role (OQ-015).

Indexes: `(occurred_at DESC)`, `(subject_user_id, occurred_at DESC)`, `(event_type, occurred_at DESC)`.

Event type catalogue: `LoginSucceeded`, `LoginFailed`, `AccountLockedOut`, `PasswordChanged`, `PasswordResetRequested`, `PasswordResetCompleted`, `EmailChangeRequested`, `EmailChanged`, `MfaEnabled`, `MfaDisabled`, `RecoveryCodesRegenerated`, `RecoveryCodeUsed`, `ExternalLoginLinked`, `ExternalLoginUnlinked`, `PasskeyRegistered`, `PasskeyRemoved`, `SessionRevoked`, `AllSessionsRevoked`, `AccountDisabled`, `AccountReactivated`, `GlobalRoleAssigned`, `GlobalRoleRemoved`, `AccountDeleted`, `AdminUserSearched`.

Plus the module's own `identity.outbox_messages` (Section 5.9).

### Outbox and inbox (every module with events)

SAD §7.8 lists `OutboxMessages` under Notifications. A business transaction can only write its own module's tables, so **each publishing module has its own outbox table in its own schema**, and the Notifications `outbox_messages` is just one of them (TD-001).

```sql
CREATE TABLE {schema}.outbox_messages (
  id             uuid PRIMARY KEY,        -- event id, also the consumers' dedupe key
  event_type     text        NOT NULL,    -- e.g. 'todos.todo-completed'
  event_version  integer     NOT NULL,
  payload        jsonb       NOT NULL,
  correlation_id text        NULL,
  occurred_at    timestamptz NOT NULL,
  attempts       integer     NOT NULL DEFAULT 0,
  next_attempt_at timestamptz NOT NULL,
  claimed_by     text        NULL,
  claimed_until  timestamptz NULL,
  processed_at   timestamptz NULL,
  status         text        NOT NULL DEFAULT 'Pending',  -- Pending | Processed | DeadLettered
  last_error     text        NULL
);
CREATE INDEX ix_{schema}_outbox_pending ON {schema}.outbox_messages (next_attempt_at)
  WHERE status = 'Pending';

CREATE TABLE {schema}.inbox_messages (          -- every consuming module
  consumer   text        NOT NULL,              -- handler type name
  message_id uuid        NOT NULL,
  processed_at timestamptz NOT NULL,
  PRIMARY KEY (consumer, message_id)
);
```

Retention: processed outbox rows older than 14 days and inbox rows older than 30 days are purged by the cleanup job. Dead-lettered rows are retained until resolved by an operator.

# 6. Integration Events

## 6.1 Event Standard

```csharp
public interface IIntegrationEvent
{
    Guid EventId { get; }            // = outbox_messages.id, the consumers' dedupe key
    DateTimeOffset OccurredAt { get; }
}
```

| Rule | Detail |
| --- | --- |
| Naming | Past tense, record in the publishing module's `*.Contracts.Events`. Wire name `module.kebab-name` (for example `todos.todo-completed`). |
| Versioning | Additive changes only within a version. A breaking change publishes `...-v2` in parallel until all consumers migrate (SAD §8.2). |
| Payload | Identifiers and minimal facts only. No personal data beyond ids, no titles or comment text unless a consumer needs it for a notification (see TD-014). |
| Delivery | At-least-once. Consumers MUST be idempotent via `inbox_messages`. |
| Ordering | Not guaranteed across events. Consumers use `OccurredAt` and state checks (for example `todo_facts.last_event_at`) to ignore stale events. |
| Failure | 10 attempts, exponential backoff (Section 12.2), then `DeadLettered` and an alert. |

## 8.1 Todo

## 9.2 UpdateTodo, CompleteTodo, ReopenTodo (US-TODO-004/005/006)

### UpdateTodo

| Aspect | Specification |
| --- | --- |
| Route | `PATCH /api/v1/todos/{id}` with `If-Match`, JSON merge-patch body. |
| Authorization | `ITodoAuthorizer.CanEdit` (module-internal, Section 11.3). Not visible → 404. Visible but not editable → 403. Soft-deleted → 404. Archived todos are read-only → 409 `todo_archived`. |
| Validation | Same field rules as create. `status` may only be `Pending` or `InProgress`. Setting `status: Completed` → 400 `use_complete_endpoint`. |
| Algorithm | Load tracked, compare `If-Match` with current `xmin` (mismatch → 409 `concurrency_conflict`), apply patch through `todo.Update(…)` which records `ChangedFields`, set `updated_at`, emit `TodoUpdated` only if something changed, save. A `DbUpdateConcurrencyException` at save time maps to the same 409. |
| Transitions | `Pending ↔ InProgress` only. Any other requested transition → 409 `invalid_state_transition`. |

### CompleteTodo

1. Load the todo (global filter hides soft-deleted). Authorize `CanComplete` (Guests: denied in R1, TD-006).
2. If `status = Completed`, return 200 with the current todo. **No write, no event** (US-TODO-005: repeated completion creates no duplicate events).
3. `todo.Complete(userId, now)` sets `status = Completed`, `completed_at = now`, `completed_by_user_id = userId`.
4. Add `TodoCompleted` to the outbox, `SaveChangesAsync`.
5. On `DbUpdateConcurrencyException`: reload once; if the todo is now `Completed` return 200 (another request won), otherwise retry once, then 409.

The DB `CHECK ck_todo_items_completion` is the second line of defence for BR-TODO-005.

### ReopenTodo

Only `Completed` todos change. `status → Pending`, `completed_at = NULL`, `completed_by_user_id = NULL`. The completion history survives in `collaboration.todo_activities` (via `TodoReopened`/`TodoCompleted` events) and in `reporting.todo_facts`; this is the agreed lifecycle policy for BR-TODO-006 (TD-017). Reopening a non-completed todo returns 200 without change.

Tests: TC-COMPLETE-01 happy path sets `completedAt`; -02 idempotent second call produces one outbox row only; -03 concurrent double completion yields one event; -04 other user's personal todo → 404; -05 Member of workspace completes; -06 reopen clears `completedAt`; -07 stale `If-Match` → 409; -08 DB constraint rejects `Completed` without timestamp (direct SQL test).

| Delete | Owner only. Body `{confirmName}` must equal the workspace name (400 `confirmation_mismatch`). Event `WorkspaceDeleted` triggers, asynchronously and idempotently: Todos soft-deletes all workspace todos, Collaboration keeps its records (hidden because the todos are hidden), Scheduling cancels reminders and ends recurrence rules, Organization soft-deletes workspace categories and tags. Physical purge after the retention period (OQ-007/OQ-015) by the cleanup job. |
| Ordering guarantee | Authorization for any workspace-scoped slice checks workspace status first, so a late consumer cannot expose data of a deleted workspace. |

## 9.6 InviteMember (US-MEM-001, FR-WS-020/021)

| Aspect | Specification |
| --- | --- |
| Route | `POST /api/v1/workspaces/{id}/invitations` `{ email, role }`. |
| Validation | `email` RFC-valid, ≤ 254 chars; normalized (trim, Unicode NFKC, lower-case). `role` ∈ `Admin, Member, Guest`; `Owner` → 400 `invalid_role`. |

Store only `SHA256(raw)` in `token_hash`. 5. `expires_at = now + 7 days`. 6. | Tests | TC-INVITE-01 Admin invites Member; -02 Admin cannot invite Admin (403); -03 Member cannot invite; -04 duplicate pending 409; -05 already member 409; -06 DB has hash not token; -07 email sent exactly once under duplicate event delivery; -08 non-member 404. |

## 9.7 AcceptInvitation (US-MEM-002, FR-WS-022)

| Step | Rule |
| --- | --- |
| 1 | Authenticated user with a confirmed email (403 `email_not_confirmed` otherwise). Token from body. |
| 2 | Look up `token_hash = SHA256(token)`. Not found → 404 `invitation_not_found` (no hint whether the token ever existed). |

A unique violation on `ux_workspace_members_active` is treated as "already a member" (the invitation still ends as Accepted). |

## 9.8 AssignTodo (US-COL-001, BR-COL-001)

1. `ITodoAccess.GetAccessAsync(todoId, me)`: `null` or `View = Hidden` → 404.
2. `access.WorkspaceId == null` → 400 `personal_todo_not_assignable` (OQ-005).
3. `IWorkspaceAccess.HasPermissionAsync(ws, me, TodoAssign)`; archived workspace → 409; else 403.
4. `FilterActiveMembersAsync(ws, [assigneeId])` must contain the assignee, else 409 `assignee_not_member`.
5. At most 10 assignees per todo (proposed) → 409 `too_many_assignees`.
6. INSERT `todo_assignees` (+ activity row, + outbox `TodoAssigned`) in one transaction. The partial unique index maps a duplicate to 409 `already_assigned`.
7. Notifications consumer skips self-assignment and honours preferences (US-NOT-004).

Guests can be assigned; assignment is what makes the todo visible to them (Section 11.3).

## 9.9 AddComment (US-COL-004, US-COL-008)

1. Todo must be workspace-scoped and viewable (`ITodoAccess`).
2. Permission `CommentCreate` (Guests only on todos assigned to them).
3. Validate `body` 1–5,000 (trimmed, not whitespace only). `mentionedUserIds` distinct, ≤ 20.
4. Each mentioned user must be an active member who can view the todo: `ITodoAccess.GetAccessAsync(todoId, mentionedId).View == Allowed`. Otherwise 400 `invalid_mention`.
5. INSERT `todo_comments` (`author_user_id = me`), activity `CommentAdded`, outbox `CommentAdded` and one `UserMentioned` per mention.
6. Notifications fan-out: mentioned users get `Mention`; assignees and watchers get `CommentAdded`; the author is never notified; one notification per recipient per comment (a mention wins over a plain comment notification).

## 9.11 Dashboard and Export (US-REP-001..005)

- **GetPersonalDashboard**: aggregates `reporting.todo_facts` where `owner_user_id = @me AND workspace_id IS NULL AND NOT is_deleted AND NOT is_archived`. `scope=all` adds workspace todos assigned to the caller (`@me = ANY(assignee_user_ids)`, restricted to workspaces where the caller is still an active member via `IWorkspaceAccess`). Day and week boundaries are computed in SQL with `AT TIME ZONE @tz` using the caller's `timeZoneId` (Section 2.1). Empty data returns zeros, never 404.
- **GetWorkspaceDashboard / GetMemberSummary**: require `ReportsView` / `ReportsMembers`. Personal todos never appear in facts queries that filter by `workspace_id`, so privacy is structural. Member summary counts come from `assignee_user_ids`; display names come from `IUserDirectory`.
- **ExportTasks**: personal export uses the caller's own filter set. Workspace export needs `ReportsExport`. The slice resolves rows through `ITodoQuery.StreamForExportAsync` (authorization is applied inside Todos again, TD-019), writes CSV from an `IAsyncEnumerable`, UTF-8 with BOM, RFC 4180 quoting. Cells beginning with `=`, `+`, `-`, `@`, tab or CR are prefixed with `'` to prevent spreadsheet formula injection. A hard cap of 50,000 rows returns 413 `export_too_large` (asynchronous exports are a future enhancement). Columns: `Id, Title, Description, Status, Priority, DueAt, CompletedAt, CreatedAt, Workspace, Category, Tags, Assignees`.

| Slice group | Technical rules that are easy to miss |
| --- | --- |

| Entity | States and transitions |
| --- | --- |

## 11.3 Evaluation Algorithm

A single module-internal authorizer per module implements the rules below. **Global roles are never consulted for workspace data** (BR-WS-005, US-MEM-010). A unit test asserts that a `PlatformAdministrator` who is not a member receives `Hidden`.

```text
TodoAuthorizer.GetAccess(todo, userId):
  if todo.DeletedAt != null                         -> Hidden (except restore path)
  if todo.WorkspaceId == null:
        return todo.OwnerUserId == userId ? Allowed : Hidden        // BR-TODO-002
  m = IWorkspaceAccess.GetMembership(todo.WorkspaceId, userId)
  if m == null or !m.IsActiveMember                  -> Hidden
  if workspace.Status == Deleted                     -> Hidden
  if m.Role == Guest and !IAssignmentQuery.IsAssigned(todo.Id, userId) -> Hidden
  view = Allowed
  edit = RolePermissions.Has(m.Role, TodoUpdate)
         and workspace.Status == Active and todo.ArchivedAt == null
         ? Allowed : Denied
  return (view, edit)
```

Membership is cached per request only (scoped service). There is no cross-request cache, so a role change or removal takes effect on the very next request (US-MEM-007/008; USAC cross-functional criterion "removed member loses access"). If load tests require a cache, use a short TTL (≤ 5 s) keyed by `(workspaceId, userId)` and invalidated by `MemberRoleChanged` and `MemberRemoved` in the same process.

# 12. Background Processing Design

## 12.1 Worker Jobs

`Todo.Worker` is a .NET Generic Host with `BackgroundService` loops. It registers all modules but no endpoints. Each loop catches exceptions per batch, logs with a correlation ID, and continues.

| Job | Module | Interval (proposed) | Batch | Claim strategy |
| --- | --- | --- | --- | --- |
| Outbox dispatcher (one loop per module outbox) | all publishers | 2 s (optionally woken by `LISTEN/NOTIFY`) | 50 | `FOR UPDATE SKIP LOCKED` + lease |
| Email sender | Notifications | 5 s | 20 | same |
| Reminder processor | Scheduling | 30 s | 100 | same |
| Recurrence generator | Scheduling | 60 s | 50 rules | same |
| Invitation expiry | Workspaces | 15 min | 500 | single `UPDATE … WHERE status='Pending' AND expires_at <= now()` |
| Session cleanup | Identity | 1 h | 1,000 | delete rows expired more than 30 days ago |
| Retention / purge | Todos, Workspaces, Identity, Notifications | daily 02:00 UTC | bounded | per policy (TD-012, OQ-015) |
| Outbox/inbox purge | all | daily | 5,000 | `DELETE` via CTE with `LIMIT` |

Worker health: the host exposes `/health/live` and `/health/ready` on an internal port and a gauge `worker_last_cycle_timestamp{job}`. An alert fires when a job's last cycle is older than 5× its interval (US-PLAT-005, SAD §14).

## 12.2 Claiming and Retry Pattern

```sql
WITH due AS (
  SELECT id FROM {schema}.outbox_messages
  WHERE status = 'Pending'
    AND next_attempt_at <= now()
    AND (claimed_until IS NULL OR claimed_until < now())
  ORDER BY occurred_at
  LIMIT @batch
  FOR UPDATE SKIP LOCKED)
UPDATE {schema}.outbox_messages m
SET claimed_by = @worker, claimed_until = now() + interval '2 minutes', attempts = attempts + 1
FROM due WHERE m.id = due.id
RETURNING m.*;
```

The lease (`claimed_until`) makes a crashed worker's rows eligible again after 2 minutes without manual action. Several worker instances can run concurrently (NFR-SCA-002).

Retry delay for attempt *n*: `min(10 s × 2^(n−1), 1 h)` with ±20 % jitter. After 10 attempts the message becomes `DeadLettered`, the metric `outbox_dead_lettered_total` increments and an alert is raised. Operators requeue a message by setting `status='Pending', attempts=0` (documented runbook; no UI in R1).

## 12.3 Outbox Dispatch and Consumers

1. Claim a batch (above).
2. For each message resolve the CLR type from `IntegrationEventRegistry` (`event_type` + `event_version`).
3. Resolve all `IIntegrationEventHandler<T>` for that type. Each handler runs in **its own scope and transaction**:
   - `BEGIN`; `INSERT INTO {consumer_schema}.inbox_messages (consumer, message_id) ON CONFLICT DO NOTHING`.
   - If 0 rows were inserted the message was already processed: skip.
   - Run the handler's changes and `COMMIT`.
4. When every handler has succeeded, set `status='Processed', processed_at=now()` (and null sensitive payload fields). If a handler fails, only that handler is retried on the next attempt; handlers that already committed are skipped thanks to the inbox.
5. Handlers must tolerate out-of-order events (compare `OccurredAt` with stored state).

## 12.4 Recurrence Generation (US-SCH-002)

**Occurrence calculation.** Occurrence *n* (0-based) is computed from the rule start, not from the previous occurrence, to avoid drift. Using NodaTime and the rule's IANA zone:

| Frequency | Local date/time of occurrence *n* |
| --- | --- |
| Daily | `start_local + n × interval` days |
| Weekly | weeks stepping by `interval`; inside each week the sorted `by_weekdays`; occurrences before `start_local` are skipped |
| Monthly | month `start + n × interval`; day = `by_month_day` (or the start day); `-1` or a day beyond the month length is clamped to the last day of that month |
| Yearly | `start_local + n × interval` years; 29 Feb in non-leap years → 28 Feb |

The local time is converted with `zone.ResolveLocal(local, Resolvers.LenientResolver)`: a non-existent time (spring-forward gap) is shifted forward by the gap length; an ambiguous time (fall-back) resolves to the **earlier** instant. This is the DST rule required by FR-SCH-012 and is covered by golden tests for `America/New_York`, `Europe/London`, `Australia/Lord_Howe` and `Asia/Ho_Chi_Minh` (no DST).

**Generation cycle.**

1. Claim up to 50 rules where `status='Active' AND next_occurrence_utc <= now()` with `FOR UPDATE SKIP LOCKED` (a short transaction that only sets a lease).
2. For each rule, loop over at most 10 due occurrences (catch-up after downtime; occurrences older than 30 days are recorded as `Skipped` in `scheduled_occurrences`).
3. Call `ITodoOccurrenceFactory.CreateOccurrenceAsync(templateTodoId, ruleId, n, dueAt)`. Todos creates the todo, and `ux_todo_items_occurrence` protects `(recurrence_rule_id, n)`. On a unique violation it returns the existing todo, so retry is safe (BR-SCH-003/005). The new todo copies title, description, priority, category, workspace and owner from the template; assignees and reminders are **not** copied in R3 (TD-021).
4. In Scheduling's own transaction: INSERT `scheduled_occurrences`, increment `occurrences_generated`, compute the next occurrence and set `next_occurrence_utc` (or `status='Ended'` when `max_occurrences` or `ends_on_local` is reached).
5. A crash between steps 3 and 4 is harmless: the next cycle repeats step 3 (idempotent) and completes step 4. No distributed transaction is needed.
6. An error on a rule is recorded in `last_error`, counted in `recurrence_failures_total`, and the rule is retried with backoff; other rules continue.

`generation_policy = AfterCompletion`: `next_occurrence_utc` stays `NULL` after generating occurrence *n* and is set when `TodoCompleted` arrives for that occurrence (next local date = completion local date + interval, same time of day). The default is `OnSchedule` (OQ-016, TD-022).

## 12.5 Reminder Processing (US-SCH-005..007)

1. Claim `Scheduled` reminders with `remind_at_utc <= now()` using the Section 12.2 pattern; set `Processing`.
2. In the same transaction publish outbox `ReminderDue` and set `Sent`, `processed_at`.
3. Notifications' consumer calls `IReminderValidation.IsStillActiveAsync(reminderId)` before creating the notification or email. If the reminder was cancelled or skipped, nothing is sent. `DeleteReminder` runs `UPDATE … SET status='Cancelled' WHERE id=@id AND status IN ('Scheduled','Processing','Sent')` and commits before returning; `IsStillActiveAsync` returns false for `Cancelled`, so after the DELETE response no reminder is sent (US-SCH-007).
4. Recompute: `TodoUpdated` with a changed `DueAt` recalculates `BeforeDue` reminders; `TodoCompleted`, `TodoDeleted`, `WorkspaceArchived`/`WorkspaceDeleted` and `MemberRemoved` skip the affected reminders; `TodoRestored` reinstates them if still in the future.
5. A reminder whose computed time is already in the past is rejected at creation (400 `reminder_in_past`); on a due-date change that moves it into the past it becomes `Skipped`.

## 12.6 Email Delivery (US-NOT-005)

1. A notification consumer (or `ISecureEmailQueue`) INSERTs an `email_deliveries` row (`Queued`) in the Notifications transaction. Preferences are evaluated here; a forbidden email is stored as `Suppressed` for traceability.
2. The sender claims rows, unprotects the payload, renders the template (Scriban, embedded resources, one file per `template_key` and locale, falling back to `en`), and calls `IEmailProvider.SendAsync(message, idempotencyKey: deliveryId)`.
3. Transient errors (timeouts, 4xx throttling) → `RetryScheduled`, delays 1 min, 5 min, 15 min, 1 h, 3 h, 6 h. Permanent errors (invalid address, 5xx policy rejection) or the 7th failure → `Failed` with a metric and alert.
4. On `Sent` or `Failed` the sender sets `protected_payload = NULL`. `last_error` stores a sanitized provider code and message, never the message body or links (US-NOT-006).
5. The provider sits behind an interface (`SmtpEmailProvider`, `SesEmailProvider`, `LogEmailProvider` for local development). The choice is OQ-010.

- One fetch wrapper sets `credentials: 'include'` and attaches `X-XSRF-TOKEN` (token loaded at start-up from `GET /auth/antiforgery`, refreshed after login and logout).
- Responses with `application/problem+json` become `ApiError { status, code, detail, errors, correlationId }`. Components branch on `code`.
- Global handling: 401 → clear the user cache and go to `/login?returnUrl=` (except for the initial `GET /me` probe); 403 → permission message; 409 `concurrency_conflict` → refetch and show "This item changed. Review the latest version"; 429 → honour `Retry-After`; 500 → generic message that shows `correlationId`.
- ETags: query data keeps the `ETag` of the last fetched resource; mutations send it as `If-Match`.

## 13.3 Server State, Keys and Invalidation

| Query key | Source | Invalidated by |
| --- | --- | --- |
| `['me']` | `GET /me` | login, logout, profile or preference changes, MFA changes |
| `['todos','list', scope, filters]` | `GET /todos` | any todo mutation in that scope |
| `['todos','detail', id]` | `GET /todos/{id}` | mutation of that todo, subtask, tag, assignee or reminder |
| `['workspaces']`, `['workspace', id, 'me']` | `/workspaces`, `/workspaces/{id}/me` | membership or role changes, invitation acceptance |
| `['workspace', id, 'members']`, `['workspace', id, 'invitations']` | members, invitations | invite, cancel, role change, removal |
| `['todo', id, 'comments']`, `['todo', id, 'activity']` | collaboration | add/edit/delete comment, assignment, completion |
| `['categories', scope]`, `['tags', scope]` | organization | create, update, delete |
| `['notifications', 'unread']` | `GET /notifications/unread-count` | mark read; **polled every 30 s while the tab is visible** (real-time is a Could, FR-NOT-011) |
| `['dashboard', scope]` | reporting | completion mutations (stale time 30 s; projection lag is acceptable) |

Pinia holds only the active workspace id (non-sensitive, validated against `['workspaces']` on load), UI preferences and navigation state (SAD §11.3).

## 13.4 Forms, Optimistic Updates and UX States

- Forms use `vee-validate` with `zod` schemas in each feature's `schemas/` folder, mirroring the limits in Section 2.2. Server `errors` map to fields by name.
- Completing a todo is optimistic with rollback on error. Every other mutation waits for the server.
- Every list and detail view implements loading, error with retry, and empty states with guidance (NFR-UX-003/004). Destructive actions (delete workspace, remove member, disable MFA) use a confirmation dialog; workspace deletion requires typing the workspace name.
- Accessibility (NFR-UX-005/006): semantic HTML, focus management on route and dialog changes, visible focus, keyboard operation of lists and menus. Playwright runs `axe-core` on every top-level route.
- Comment bodies and all user text are rendered as text, never as HTML.
- Time: the UI shows dates in the user's `timeZoneId` and sends instants as UTC ISO strings. Recurrence forms send local time plus zone id (Section 8.4).

# 14. Test Design

## 14.1 Minimum Tests per Slice

A slice is not Done (Section 15.3) until it has:

| Layer | Requirement |
| --- | --- |
| Domain unit | Every invariant and state transition in the aggregate, including illegal transitions. |
| Validator unit | One test per validation rule (boundary values). |
| Integration | One happy path and one test per error code in the slice's error table, through `WebApplicationFactory` against real PostgreSQL. |
| Authorization | The rows of Section 11.2 relevant to the slice: allowed role, denied role, non-member (404), anonymous (401). |
| Persistence | Asserts the stored row (UTC timestamps, owner derived from the caller, outbox row in the same transaction). |
| Contract | The OpenAPI document is snapshot-tested; a breaking change (oasdiff) fails CI. |

## 14.2 Test Infrastructure

| Concern | Approach |
| --- | --- |
| Database | Testcontainers PostgreSQL, one container per test collection. The schema is created from migrations (so migrations are tested). Data is reset with Respawn between tests. |
| Time | `FakeTimeProvider` registered in the test host. No `Thread.Sleep`. |
| Authentication | Helper `Client.AsUser(userId, roles)` issues a real cookie through the Identity pipeline; `AsAnonymous()` for 401 cases. |

| Data builders | `TodoBuilder`, `WorkspaceBuilder` seed through public slices or module services, not raw SQL, except in constraint tests. |

## 14.4 Security Test Suite (USAC Part XIV)

- **IDOR sweep (generated):** the suite reads the OpenAPI document, creates two users and two workspaces, and calls every route that has an id parameter with the other user's resource ids. Expected: 404 (or 403 only where Section 7 says the resource is visible). A new route without coverage fails the sweep.
- **Matrix tests:** Section 11.2 is encoded as data; one parametrised test per permission and role.
- **Role escalation:** an Admin cannot invite an Admin, change the Owner or self-promote; a global PlatformAdministrator gets 404 on a workspace they do not belong to.
- **Session security:** a revoked session is rejected on the next request; password change and disable invalidate sessions; cookie attributes are asserted.
- **CSRF:** every state-changing route returns 400 without `X-XSRF-TOKEN`.
- **Rate limiting:** auth endpoints return 429 with `Retry-After` after the configured threshold.
- **Secrets:** a log-capture test asserts that passwords, tokens and recovery codes never appear in logs or audit `data` (NFR-SEC-005).
- **Enumeration:** login, forgot-password and resend-confirmation responses are identical for existing and non-existing emails (except documented TD-015).

## 14.5 Concurrency, Idempotency and Time

| Area | Tests |
| --- | --- |
| Optimistic concurrency | Two parallel `PATCH` calls with the same ETag: exactly one succeeds, the other gets 409. |
| Idempotent transitions | Double `complete`, `archive`, `watch`, `delete`: one outbox event only. |
| Parallel acceptance | Ten parallel `accept` calls on one invitation: one membership; every other response is 200 (same user) or 410. |
| Event duplication | Deliver the same outbox message twice to every consumer: no duplicate notification, activity row or fact change. |
| Worker concurrency | Two worker instances over the same data: each reminder and occurrence is processed exactly once. |
| Crash recovery | Kill the worker between recurrence steps 3 and 4: the next run completes without duplicates. |
| DST and zones | Golden tables of occurrence instants for the four zones in Section 12.4 across two DST transitions; month-end clamping; leap-day yearly rule. |
| Reporting boundaries | A completion at 23:30 local on the last day of a week lands in the correct week for `Asia/Ho_Chi_Minh` and `America/Los_Angeles`. |

## A.2 Domain Aggregate

Business rules live here, not in handlers. The constructor is private so an invalid `TodoItem` cannot exist.

```csharp
namespace Todo.Modules.Todos.Domain;

internal enum TodoStatus { Pending, InProgress, Completed }
internal enum TodoPriority { Low, Medium, High, Urgent }

internal static class TodoErrors
{
    public static readonly Error TitleRequired = new("validation_failed", "Title is required.", ErrorKind.Validation);
    public static readonly Error NotFound = new("not_found", "Todo not found.", ErrorKind.NotFound);
    public static readonly Error Archived = new("todo_archived", "Archived todos are read-only.", ErrorKind.Conflict);
    public static readonly Error InvalidTransition = new("invalid_state_transition", "This status change is not allowed.", ErrorKind.Conflict);
}

internal sealed class TodoItem
{
    public const int TitleMaxLength = 200;

    private TodoItem() { }                       // required by EF Core only

    public Guid Id { get; private set; }
    public string Title { get; private set; } = default!;
    public string? Description { get; private set; }
    public Guid OwnerUserId { get; private set; }
    public Guid? WorkspaceId { get; private set; }
    public Guid? CategoryId { get; private set; }
    public TodoStatus Status { get; private set; }
    public TodoPriority Priority { get; private set; }
    public DateTimeOffset? DueAt { get; private set; }
    public DateTimeOffset? CompletedAt { get; private set; }
    public Guid? CompletedByUserId { get; private set; }
    public DateTimeOffset? ArchivedAt { get; private set; }
    public DateTimeOffset? DeletedAt { get; private set; }
    public DateTimeOffset CreatedAt { get; private set; }
    public DateTimeOffset UpdatedAt { get; private set; }
    public uint Version { get; private set; }    // mapped to xmin (A.3)

    public static Result<TodoItem> Create(
        Guid id, string? title, string? description, TodoPriority priority,
        DateTimeOffset? dueAt, Guid ownerUserId, Guid? workspaceId, Guid? categoryId,
        DateTimeOffset now)
    {
        var trimmed = title?.Trim();
        if (string.IsNullOrEmpty(trimmed) || trimmed.Length > TitleMaxLength)
            return Result<TodoItem>.Fail(TodoErrors.TitleRequired);

        return Result<TodoItem>.Ok(new TodoItem
        {
            Id = id, Title = trimmed, Description = description?.Trim(),
            OwnerUserId = ownerUserId, WorkspaceId = workspaceId, CategoryId = categoryId,
            Status = TodoStatus.Pending, Priority = priority, DueAt = dueAt,
            CreatedAt = now, UpdatedAt = now
        });
    }

    public Result<bool> Complete(Guid userId, DateTimeOffset now)
    {
        if (Status == TodoStatus.Completed) return Result<bool>.Ok(false);   // false = nothing changed
        Status = TodoStatus.Completed;
        CompletedAt = now; CompletedByUserId = userId; UpdatedAt = now;
        return Result<bool>.Ok(true);                                         // true = state changed, emit event
    }

    public Result<bool> Reopen(DateTimeOffset now)
    {
        if (Status != TodoStatus.Completed) return Result<bool>.Ok(false);
        Status = TodoStatus.Pending;
        CompletedAt = null; CompletedByUserId = null; UpdatedAt = now;
        return Result<bool>.Ok(true);
    }
}
```

Pattern to copy: methods return `Result<bool>` where `true` means "state changed, publish an event" and `false` means "already in that state, do nothing". This is how idempotency (Section 2.5) is implemented without `if` chains in handlers.

## A.6 Handler

```csharp
internal sealed class CreateTodoHandler(
    TodosDbContext db,
    ICurrentUser user,
    IWorkspaceAccess workspaces,
    ICategoryAccess categories,
    IValidator<CreateTodoRequest> validator,
    IOutboxWriter<TodosDbContext> outbox,
    TimeProvider clock)
{
    public async Task<Result<CreateTodoResponse>> HandleAsync(CreateTodoRequest r, CancellationToken ct)
    {
        // 1. Shape validation
        var v = await validator.ValidateAsync(r, ct);
        if (!v.IsValid) return Result<CreateTodoResponse>.Fail(v.ToError());

        var userId = user.UserId;                       // never from the request (US-TODO-001)
        var priority = r.Priority is null ? TodoPriority.Medium : Enum.Parse<TodoPriority>(r.Priority);

        // 2. Authorization for workspace todos
        if (r.WorkspaceId is { } wsId)
        {
            var m = await workspaces.GetMembershipAsync(wsId, userId, ct);
            if (m is null || !m.IsActiveMember)
                return Result<CreateTodoResponse>.Fail(TodoErrors.NotFound);          // Hidden -> 404
            if (m.WorkspaceIsArchived)
                return Result<CreateTodoResponse>.Fail(new("workspace_archived", "The workspace is archived.", ErrorKind.Conflict));
            if (!await workspaces.CanCreateTodoAsync(wsId, userId, ct))
                return Result<CreateTodoResponse>.Fail(new("permission_denied", "You cannot create todos here.", ErrorKind.Forbidden));
        }

        // 3. Cross-module reference check
        if (r.CategoryId is { } catId && !await categories.CanUseCategoryAsync(catId, userId, r.WorkspaceId, ct))
            return Result<CreateTodoResponse>.Fail(new("invalid_category", "Category is not available.", ErrorKind.Validation));

        // 4. Domain
        var created = TodoItem.Create(Guid.CreateVersion7(), r.Title, r.Description, priority,
            r.DueAt, userId, r.WorkspaceId, r.CategoryId, clock.GetUtcNow());
        if (!created.IsSuccess) return Result<CreateTodoResponse>.Fail(created.Error);
        var todo = created.Value;

        // 5. Persist state and event in one transaction
        db.TodoItems.Add(todo);
        outbox.Add(new TodoCreated(Guid.CreateVersion7(), clock.GetUtcNow(),
            todo.Id, todo.OwnerUserId, todo.WorkspaceId, todo.Status.ToString(), todo.Priority.ToString(), todo.DueAt));
        await db.SaveChangesAsync(ct);

        return Result<CreateTodoResponse>.Ok(new(todo.Id, todo.Title, todo.Status.ToString(),
            todo.Priority.ToString(), todo.DueAt, todo.WorkspaceId, todo.CreatedAt));
    }
}
```

## A.11 What To Notice (review checklist for this slice)

1. The owner comes from `ICurrentUser`; the request type has no owner field.

## B.2 Where Does This Code Go?

| I need to | Put it in | Never in |
| --- | --- | --- |
| Check a field length or format | `Validator.cs` | handler or aggregate (aggregates still guard invariants) |

## B.4 Pitfalls Checklist (reviewers use this list)

1. A request record contains `UserId`, `OwnerUserId` or `AuthorUserId`.
2. A query on a user-owned table has no owner or membership filter.
3. 403 returned where the caller must not learn the resource exists (should be 404).
4. A handler calls another module's `DbContext` or uses its entity type.
5. `SaveChangesAsync` called twice in one handler (state and outbox no longer atomic).
6. Event published directly (HTTP call, in-memory bus) instead of the outbox.
7. A consumer that is not idempotent or assumes events arrive in order.
8. `DateTime.Now`, `DateTime.UtcNow` or `DateTimeOffset.Now` used.
9. Enum stored as integer, or a status string typed by hand instead of the enum.
10. List endpoint without `ORDER BY ... , id` (unstable paging) or without a `pageSize` maximum.
11. N+1 queries: a loop that calls a contract per row (use the batch methods in Section 4.3).
12. Password, token, recovery code, email body or comment text written to logs or audit `data`.
13. Business rule written only in the frontend or only in a validator.
14. Soft-deleted rows visible because `IgnoreQueryFilters()` was used without a reason comment.
15. Missing `Produces`/`ProducesProblem` metadata, so the OpenAPI snapshot is incomplete.
16. New route without an IDOR sweep entry or role-matrix test.
17. Migration that drops or renames a column in the same release as the code that stops using it.
18. Time zone conversion done with `TimeZoneInfo` (use NodaTime and IANA ids).
19. Error message that reveals whether an email, token or id exists (login, reset, resend, invitations).
20. `catch (Exception)` that swallows an error and returns success.

# Appendix C. Specification of Remaining Slices

Format for each slice: **Request** (fields and validation), **AuthZ**, **Steps**, **Errors**, **Events**, **Tests**. Common rules apply everywhere and are not repeated: authentication required unless marked Anon, antiforgery on every state-changing call, owner or actor taken from `ICurrentUser`, UTC timestamps, deterministic ordering, error body per Section 2.3.1. Test IDs `TC-<SLICE>-nn` are the minimum cases; each error listed needs one test, plus the happy path.

## C.1 Identity

### C.1.1 RegisterUser (US-IAM-001)

- **Request:** `{ email, password, displayName }`. Email RFC-valid, ≤ 254, normalized lower-case. Password per policy (Section 2.6), ≤ 128. `displayName` 1–100 trimmed. Anon, rate-limited.
- **Steps:** check existing normalized email; `UserManager.CreateAsync`; add role `StandardUser`; generate email-confirmation token; enqueue `email-confirmation` via `ISecureEmailQueue`; audit; no session is created (BR-IAM-002).
- **Errors:** 400 `validation_failed` (field errors include the failed password rule); 409 `email_already_registered` (TD-015); 429.
- **Events/Tests:** none published. TC-REGISTER-01 valid creates unconfirmed user and one email; -02 duplicate email (case-insensitive); -03 weak password; -04 password never in logs or response; -05 user cannot call `/me` until login.

### C.1.2 ConfirmEmail (US-IAM-002)

- **Request:** `{ userId, token }` (token from the email link, URL-safe base64). Anon.
- **Steps:** `UserManager.ConfirmEmailAsync`; already-confirmed user returns 204 (idempotent); audit.
- **Errors:** 400 `token_invalid`; 410 `token_expired` (lifespan 24 h via `DataProtectionTokenProviderOptions`).
- **Tests:** TC-CONFIRM-01 valid; -02 reused token on already confirmed user returns 204; -03 tampered token 400; -04 expired token 410 (fake clock).

### C.1.3 ResendEmailConfirmation (US-IAM-003)

- **Request:** `{ email }`. Anon, rate-limited (3 per hour per email).
- **Steps:** if user exists and is unconfirmed, enqueue a new confirmation email (older tokens stay valid until expiry, since the Identity token provider is stateless). Always respond 202 with the same body.
- **Tests:** TC-RESEND-01 response identical for unknown, confirmed and unconfirmed emails; -02 only the unconfirmed case sends mail; -03 rate limit returns 429.

### C.1.4 VerifyMfa and LoginWithRecoveryCode (US-IAM-012, US-IAM-013)

- **Request:** `{ code, rememberMachine? }` or `{ recoveryCode }`. Requires the partial two-factor cookie from Login.
- **Steps:** `SignInManager.TwoFactorAuthenticatorSignInAsync` or `TwoFactorRecoveryCodeSignInAsync`; on success create `user_sessions` row, sign in with `amr = [pwd, mfa]`; recovery code is consumed (single use); audit `RecoveryCodeUsed` for recovery.
- **Errors:** 401 `invalid_code`; 403 `account_locked` (failed codes count toward lockout); 401 `mfa_session_expired` (partial cookie lifetime 5 min).

### C.8.2 Query slices

Personal totals (the model for every aggregate; time zone aware):

```sql
SELECT
  count(*)                                                        AS total,
  count(*) FILTER (WHERE status = 'Completed')                    AS completed,
  count(*) FILTER (WHERE status <> 'Completed')                   AS pending,
  count(*) FILTER (WHERE status <> 'Completed' AND due_at < now()) AS overdue,
  count(*) FILTER (WHERE status <> 'Completed'
     AND (due_at AT TIME ZONE @tz)::date = (now() AT TIME ZONE @tz)::date) AS due_today,
  count(*) FILTER (WHERE completed_at >= date_trunc('week', now() AT TIME ZONE @tz) AT TIME ZONE @tz) AS completed_this_week
FROM reporting.todo_facts
WHERE owner_user_id = @me AND workspace_id IS NULL AND NOT is_deleted AND NOT is_archived;
```

- **GetProductivityTrends:** `from`, `to` (max 366 days), `granularity` day or week; group by `date_trunc(granularity, completed_at AT TIME ZONE @tz)`; missing buckets are filled with zeros in code so charts have no gaps. **GetWorkspaceDashboard:** same aggregates with `workspace_id = @ws`; adds `byPriority` and `unassigned` counts. **GetMemberSummary:** `SELECT unnest(assignee_user_ids) AS user_id, count(*) ... GROUP BY user_id`, names from `IUserDirectory`; members with no tasks are included with zeros through `IWorkspaceAccess.GetActiveMemberIdsAsync`.
- **Tests:** TC-REP-01 zero data returns zeros; -02 counts equal seeded facts; -03 week boundary per zone; -04 Member without `ReportsView` gets 403; -05 personal todos never counted in workspace totals; -06 projector handles out-of-order events; -07 CSV formula injection prefixing; -08 export over 50,000 rows returns 413.

## E.4 Local Setup (US-PLAT-001, US-PLAT-004)

1. Install .NET SDK 10, Node.js (LTS), Docker.
2. `docker compose up -d db mail` starts PostgreSQL and a local SMTP catcher (MailHog or equivalent).
3. `dotnet run --project src/Host/Todo.Migrator` applies every module's migrations.
4. `dotnet run --project src/Host/Todo.Api` and `dotnet run --project src/Host/Todo.Worker` (both read the same `appsettings.Development.json`).
5. `npm install && npm run dev` in `src/Web` (the dev server proxies `/api` to the API so cookies stay same-site).
6. `dotnet test` runs unit, architecture and integration tests (Testcontainers needs Docker); `npm run test` and `npm run e2e` run the frontend suites.
7. Seed data: `dotnet run --project src/Host/Todo.Seeder` creates demo users, one workspace per role, and sample todos for manual testing. Seeding is refused outside the Development environment.

A new developer should reach a running system with a registered, confirmed user within 30 minutes using only this list (US-PLAT-001 acceptance criterion).
